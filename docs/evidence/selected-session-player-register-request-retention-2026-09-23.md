# Exact selected Register request retention — 2026-09-23

Unapplied review patch: `artifacts/selected-session-player-retain-register-request-20260923.patch`. It adds `CharacterRegistrationRequest` to `SelectedSessionPlayerStartup<T>` and changes only its private shared initializer: call the integrated `try_prepare_mounted_registration`, keep the returned request, then call the same existing `try_initialize` Actor path. Both public constructors still delegate to this one initializer. The legacy `try_initialize_mounted` wrapper already performs these two calls in this order, so this patch runs the recipe load and Actor initialization once, without a second map parse or Juice construction. The shared-map constructor continues to use the caller's exact `Arc<SelectedInputMap>` and `JuiceTrickInput`.

The returned request is the actual output of the retained mounted loader, including request ID, character ID, peer ID, player index and flags. It is not reconstructed from `PlayerLoadPhase`, silently chosen from a fixture, or treated as a registration-completion status. IDA `PlayerLoaderImpl::OnSimCharacterLoaded 0x82817f28` and `SimCharacterManager::Register 0x82817a08` produce a request; `PresCharacterManager::Update 0x82818f2c..82818f94` emits status only after the ordinary presentation entity exists and its full peer ID matches the registered peer. For first ordinary player, that entity is produced via Actor submit/restore, so the request may be retained while Actor and physical pair are constructed.

This patch retains the request **only on a successful constructor return**. `try_new_inner` still creates `selected` and `source` locally and returns an error without them if preparation or Actor initialization fails. The session boot owner therefore cannot yet claim inner partial-owner retention; a later constructor shape must put these owners into the session before the first fallible operation or return them in a typed failure. It also still lacks the recipe-map notification, live `SkaterPresEntity`, peer-gated status delivery and source-traced command-3 sender schedule. The patch does not invoke `PlayerLoaderSlot::character_registered` or manufacture a receipt.
