# Scripted queued physical input: bounded source audit (2026-09-23)

Scope: read-only audit of the four requested corpus/device files and their immediate conversion/tick callers. No registered Rust or Cargo change; no original-data run. The reported original suite is 21/22, while the two 120-tick queued policies currently use a constant hardware packet. This packet proposes a test, not parity evidence.

## Evidence and current mismatch

- `input_xenon_pad_device_tests.rs::Platform::get_state` always returns packet 7 with `buttons: 1` and zero sticks/triggers. `physical_player_queued_input_corpus.rs::QueuedInputCorpus::poll_and_enqueue` polls that platform once per frame, caches Simulation and Presentation, advances focus, queues the sampled player and sync command. Both `ExistingFixture` and `NativeDisabledJuice` modes share this platform. The fixture remap writes channel 0 only; disabled Juice performs its separate real disabled-boot branch. Confidence: exact for host source.
- `physical_player_three_frame_corpus.rs::check_mode` takes the queued branch for 120 frames, calls `SelectedPlayerTick::try_step_queued`, and checks admitted command count, same Actor owner, pre-solve, solve, post-solve, presentation, numeric board state and RNG index. Its `GameInputFrameRequest` contains a zero sample, but that is used by the immediate branch; queued admission uses delivered commands. The queued loop currently asserts no gesture event or trick state. Confidence: exact for host source.
- `game_input_recognizer_corpus.rs` loads the actual right-stick `Ollie` points and replays them in reverse stored order (the parser push-front stores the last authored point at index 0), with neutral and held/released samples. `game_input_loaded_action_corpus.rs::check_original_kickflip` similarly loads the actual `Kickflip` pattern, waits `Vault.waiting + 2` neutral frames, plays its chronological points, repeats the endpoint for Held, and zeroes the stick for release. It proves the same Actor listener sees the pattern, `Trick`/`Kickflip`/`HoldPattern` intents and loaded Action selection, but this is a controlled command sample path without the full physics tick. Confidence: exact for host source and mounted corpus assertions.
- `input_pad.rs::try_convert_xbox_pad` (`82989448`) maps raw signed right-stick axes through radial deadzone/normalization into channels 20/21 (positive/negative X) and 22/23 (positive/negative Y). Raw triggers map to channels 10/11. `game_input_recognizer_corpus.rs::sample_from_point` maps an authored recognizer point `[x,y]` to gameplay X=`x`, Y=`-y` before `UpdateRecognizer` negates Y. A raw packet is therefore not numerically interchangeable with an authored point: conversion, input.cfg mapping, sparse command quantization and matcher tolerance intervene. Confidence: exact for conversion; raw-to-authored inverse for arbitrary points remains a hypothesis until the mounted map is checked.
- `selected_player_tick.rs::try_step_queued` delivers the queue, calls recognition/Flush, then the actual selected Actor prefix, pre-solve, physics solve and post-solve. `SelectedTickStage::BeforeActor` fires before recognition and `BeforePreSolve` after Actor, so the existing observer alone cannot inspect listener events in the narrow interval between Flush and Actor Fill. Confidence: exact for host source.
