# Opaque selected session facade — review packet, 2026-09-23

Reviewed implementation patch: `artifacts/selected-session-public-facade-20260923.patch`. Its source is now `crates/skate2-core/src/session/selected_session_public_facade.rs`, a child of `selected_session_boot_owner`. It publicly reexports only facade value/error types and the existing Juice platform boundary, and leaves all `SelectedSession` fields private to the core crate.

## Owner and caller contract

`SelectedLiveSession<T,C>` holds exactly one registered `SelectedSession<T,C>`. `try_begin_controlled` calls its already tested prefix, controlled player/Register request, physical pair, controlled presentation, and terrain-start methods once in that order. The host supplies its pad, Juice platform/option/INI, actual animation-thread callback, stream-effects observer, mapping/physical assertions, and every remaining source policy. The public Juice visibility change is limited to `JuiceBootPlatform`, `JuiceHostOption`, endpoint/name/connection result types needed by the existing unregistered Windows Juice adapter; it adds no network answer. `SelectedSpawnPolicy::AuthoredSelectedLocation` reads `assets.spawn` **after** this same session completed `SelectedOriginalAssets`, and `SelectedGravityPolicy::VaultSkateboardDefault` reads this same retained Vault's default skateboard physics layout immediately after the boot prefix and installs gravity before physical body admission. The app need not reopen locations, Vault or mounts. Explicit transform/vector variants remain clearly host overrides.

`try_poll_controlled_boot` advances the retained `SelectedSessionTerrain` stream and resident once per call. A pending bounds read remains a typed pending poll, preserving the source and its unattempted request; other reached errors end the facade attempt with the underlying partial owner still held. After normal-arena completion it uses the registered same-world camera/roster admission, binds the same input bootstrap with the native static command-field constructors **only when the host selected `NativeStaticFields`**, and prepares one registered selected tick/presentation runtime with the host's presentation/root-W/camera-submit policy. `controlled_frame_ready` checks camera completion, presentation completion, bound input, player, pair, tick, runtime and completed terrain on the exact world Arc. It does not interpret the boot owner's broad `TerrainCameraInputAndFrameServices` hint as ready.

`try_tick` is the only public input/frame step. It polls and caches the supplied pad on the retained `SelectedProductionInputOwner`, pre-update enqueues against this player's loader and same world's `PhysicalGameInfo`, then borrows the existing `SelectedSessionFrame` once with this terrain ground pool and queue/RNG. It constructs only the already used host numeric/recognizer/feedback service values and forwards the explicit dt, LOD, focus/simulation answer, flags3, ground group, spy flags, wait answer and parked-grind exclusions. These per-tick service wrappers reference retained input/Actor history and shared manager parameters; constructing them does not reset flick/grab or freezing state. `NoCommands` leaves `last_step_completed=false`; a completed queued tick makes the same-frame runtime eligible. Any `Failed` after a mutating poll, enqueue or frame operation retains its first `SelectedLiveStage` as terminal, so later boot polls and ticks return `AlreadyFailed(stage)` rather than replaying partial writes or reporting a misleading pending state. Unsupported active-grind, other physical schedules and pipeline-culling policies return `UnsourcedFramePolicy` before those writes.

`try_visual_snapshot` returns borrowed `&CharacterPalette` and `&CharacterMaterialAdmission` from that same completed runtime plus the retained camera observer's **provisional producer** `clip_from_world` and update counter. Before a completed frame it returns `NoCompletedFrame`; a later NoCommands or failed step invalidates snapshot eligibility. The existing app GPU path consumes precisely those palette/material references and a clip matrix in `selected_character_material::{create_objects,update_object}`. The map path can use the copied clip through its existing `Inspection` object updater. This is a render input view, not a second scene, palette, material or camera constructor.

## Source evidence and limits

IDA `SkaterManager::SpawnPlayer 0x82600630` allocates the Actor/physical pair before `InitPlayer 0x826000b0` graph loading; the registered camera/frame extension preserves its bounded graph/cache/camera capture before roster publication. The registered selected tick orders queued delivery, Actor, physical stages, selected camera prefix and same-frame presentation publication; the original-data cross-owner test now passes one empty queued mask and one actual queued mask with palette and camera observer evidence. Confidence for this *controlled host composition* is high relative to that test. It is not exact native whole-session scheduling.

Typed native gaps remain exposed by `SelectedLiveSession::native_gaps()`: PlayerUI command-3 sender timing and matching Register peer/status, original enabled PROXY load/activate before BAM, and native restored `CameraPresentation`. The available projection is explicitly provisional; source `kbUsePhysOutCamera`/presentation interpolation remain outside this facade. The fixed host numeric profile, `NativeStaticFields` command initialization, root-W opaque bits, arena userdata, unlock seed, collection, DMO parallel answer, camera set, frame cadence and parked grinds are caller choices requiring further source admission; the facade supplies no defaults. A host can choose a controlled first-test path but must not label it native freeroam parity.

The independent reviewer approved the refreshed patch for integration and typecheck. Its preintegration `git apply --check --ignore-space-change` and edition-2024 `rustfmt --check` passed. The facade itself still needs Cargo typecheck and an original-data selected-session run through this public entry point; app rendering remains a separate integration gate.
