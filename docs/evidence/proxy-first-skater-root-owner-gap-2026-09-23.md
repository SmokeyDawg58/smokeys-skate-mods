# PROXY first-skater root owner and first production gap (2026-09-23)

Read-only source/caller audit of the accepted PROXY catalog path, renderer entry, and the independently reviewed unregistered upload client. The exact evidence path was absent before writing. No registered source or Cargo command was changed. Confidence is high for the native boot order and current Rust call graph; this note claims no activation or first-skater rendering. Independent review confirmed the native load-before-activate-before-normal-world order. References to a host renderer callback below describe a possible integration design, not native ordering: native Presentation already exists when PROXY loading runs. The collection and asset counts are mounted-corpus observations, not constants in native code.

## Actual native owner and order

`cGameAssetManager` constructs `cAssetStreamSystem`, which owns the retained `cProxyWorldManager` before boot (`proxy-world-boot-order-2026-09-23.md`, constructors `824dfb68`, `824de440`, `824ddef0`). `GameModule::OneOffLoad8273add8` samples live `kEnableProxyWorldStream` at `8273b41c`; with its authored true default, it calls `SyncLoadProxyWorldStream824e0710` / manager `824df648` for `data\\content\\world\\stream`, `PROXY`. It samples the cvar again at `8273b490`, calls `SyncActivateProxyWorld824d9ef8` when enabled, and only afterward starts the normal `worldFile` stream at `8273b524`. The disabled branch has different loose-asset loads; constructor-empty proxy maps are not the enabled default.

The manager owns the **same** PROXY loaded/activated counters, XSS sorted spatial IDs, and proxy membership used later by `AddHighCollection824dc678`. Load reads registered PROXY metadata, sorts XSS, issues each `LoadCollection` through the parent expansion and resident callbacks, then waits for all loaded callbacks (`824dfab8`). Activation sends ordered Presentation messages and distinct activation callbacks, then waits for all activated callbacks (`824da0cc`). Parent first-use completion also sends Simulation and Presentation registrations. A decoded collection or successful upload alone satisfies none of these waits. `AddHighCollection` consults membership, which can exist before completion; native boot nevertheless completes PROXY load and activation before beginning the normal world stream.

## Existing Rust owners and the missing edge

`WorldStreamCatalog` and `StreamFile` already parse/register metadata. `CollectionParentManager::plan_load` expresses ancestor-first requests, and `CatalogResidentCollectionLoadFactory` / `CollectionResidentStreamer` / `OwnedResidentCollectionStorage` can retain physical assets. The ignored `proxy_asset_census.rs` creates a PROXY catalog and proves the 148-collection closure with the existing driver, but it calls only `plan_load` and never delivers load/activation callbacks. It is test-only and drops its local owners. The all-PROXY asset result is 327 occurrences / 292 unique IDs, including 93 single-Texture parent arenas and 87 spatial Texture occurrences (`proxy-parent-asset-producer-audit-2026-09-23.md`).

The actual app render entry is `main.rs:205` -> `render_inspection::run` -> `render_window::run_with_options` -> `RenderWindowClient::initialize(&GpuRenderer)`. Inspection creates `PresentationScene` and a separate copied `TextureScene` before entering the window, and its GPU uploads are local diagnostic bindings (`render_inspection.rs:17-93, 106-143`). No first-skater render client or PROXY manager owner is invoked from `main`. The app's BAM world-stream probe (`main.rs:385-555`) creates its own catalog, uses observation-only `WorldStreamEffects`, optionally runs the Rob's Park resident diagnostic, then unloads. Core `SelectedWorldStream` is a retained BAM owner, but its only concrete first-skater-side caller is `physical_player_camera_stream_corpus::load`, which passes `StreamObservations`; it does not run PROXY first. `SelectedResidentStartup` is Simulation-only and selects a BAM terrain collection in `physical_player_grind_corpus`; it cannot substitute for Presentation proxy residency.

Therefore the **first missing production edge** is the retained enabled-PROXY boot composition at the GameModule/asset-stream-system boundary: obtain the actual live proxy setting, keep the PROXY stream registration and catalog owner alive, traverse sorted XSS through `CollectionParentManager` and the existing resident streamer, count real loaded callbacks, apply Presentation registration effects, count real activation callbacks, and supply that same manager to subsequent BAM `WorldStreamEffects::add_high_collection`. The current `WorldStreamEffects` trait returns `()` for high collection effects (`world_stream_runtime.rs:58-61`), limiting direct error propagation; a checked sidecar or adapter may still be possible. Native `OneOffLoad` proves activation completes before BAM starts. A host renderer callback alone cannot replace this retained startup owner, but native product-processing effects are owed during load and must not be deferred past a claimed successful load completion.

## Kind-0 boundary after the root owner exists

Once that owner feeds the actual parent-first resident callback, the 93 parent arenas enter the native single-Texture alias branch and produce kind-0 registry entries in processed order (`ProcessArena82d5fee0`, `RegisterTexture82d5ea00`). First-use Presentation `RegArena827f155c..156c` calls shader `AddTexture` with the distinct alias identity and full TOC GUID; last-use `DRegArena827f17ac..17bc` removes the same identity before product destruction. `ArenaRegistrationRefCounter` and the unregistered `proxy_shader_texture_table_draft.rs` cover decision/table mechanics but do not create or publish the product. Spatial kind-2 material and admitted kind-10 Environment effects remain required before activation completion; no DMO expansion is indicated by the observed PROXY records or userdata-zero registration.

The independent review in `artifacts/proxy-texture-resident-client-independent-review-2026-09-23.md` confirms the unregistered `proxy_texture_resident_client_draft.rs` plausibly holds decoded data and an owned upload, but it has a visitor-error compile blocker, no root invoker/PROXY membership check, no processed alias or manager effects, and an empty draw list. Keep it diagnostic and unregistered. It should not drive priority ahead of the retained boot owner or be presented as first-skater rendering.

## Safe handoff

The next bounded production packet is the retained enabled-PROXY **load owner**, rooted where `OneOffLoad` runs before the BAM `SelectedWorldStream` start. Reuse the parsed PROXY `StreamFile`, catalog and `CollectionParentManager`; send actual parent/spatial resident requests through one retained streamer and expose explicit loaded-completion state. Do not advance activation until source-ordered processed Presentation kind-0/2/10 effects and their callback completions exist. A focused real-corpus check should verify the 148 required collections, 127 parent requests with one parent first-use registration, 147 distinct spatial load callbacks, and no BAM high-collection effect before activation. That gives the renderer a genuine retained source owner to consume; the GPU upload and selected world/player draw path follow that owner rather than creating a second texture inventory.
