- `UpdateGrindDetection` first tests `CameraMan+0x248` for a detector. If present, it gets the Subject skateboard effective transform (`Subject` virtual +0x100), reads the Rig velocity at `CameraMan+0x260`, Rig+0xe0, zeros Y and W, and computes horizontal speed. - At or above the gate, `0x82e3e9d8..0x82e3ead4` safe-normalizes the horizontal velocity with a zero fallback, combines that direction with the J/up vector, rotates the frustum by negative `GameCameraParameters+0x2c0` pitch degrees (`* -0.017453292`), and offsets the Subject board position by normalized direction times `+0x2d0` grind-skater offset. This constructs a local matrix; it does not install another world, terrain or detector. `Subject::GetIsGrinding` (virtual +0x1a8) supplies the byte passed to the detector `Update` virtual +0x04 at `0x82e3eae8..0x82e3eb08`.

Its parameter reads include min/max lookahead +0x2a4/+0x2a8, lookahead time +0x2ac, horizontal/vertical angles +0x2b0/+0x2b4, relative angle +0x2b8 and board offset +0x2c4. `FindBestGrindCandidate` builds a frustum AABB (`AddPointToBox 0x82e36758`, `AddFrustumRayToBox 0x82e36900`), caps relative height at +0x2d4, then calls the process `GrindData::BoxTest` at `0x82e37628` with **ignore_vertical=false**. - Regardless of the detector `Update` result, `CameraMan` gets its current Frame (`0x82e3eb1c`), Subject skeleton hips (`Subject` virtual +0x134), and calls detector `UpdateGrindAnticipation 0x82e37338` at `0x82e3eb5c` with `dt`, current frame position and hips position. `UpdateGrindAnticipation` reads fade-in +0x2c8 and fade-out +0x2cc. ## Existing ownership and narrow continuation

`CameraMan` already holds the single `Arc<Mutex<CameraGrindDetector>>` shared by the camera construction state; it also retains the actual Subject, Rig, published camera parameters and Frame. Original Vault reading already publishes grind parameter fields (`camera_attribute_read.rs:161-173`). The combined corpus's `RetainedGrindCorpus` has admitted 21 normal plans into the same world's `PhysicalGrindServices`; its `try_box_test` uses the retained static `GrindDataRuntime` plus the installed dynamic provider (`physical_player_grind_world.rs:132-164`) and accepts `ignore_vertical=false`. A future active camera query must borrow that exact service/result, not decode a second arena or use an empty diagnostic query. `CameraSelectedInputs` currently carries LivingWorld and a weak world handle but no direct GrindData query capability, so the active path also needs an explicit same-world borrow or retained service handle; do not relock the world mutex while the selected tick holds it.

The smallest source-backed first-test continuation is to replace the positive-speed blanket `PendingGrindDetection` with a detector step over the **retained** owner. Preserve the cvar and speed gate. For this owner when `detector.active==false` (or `Subject.isGrinding==true`), perform native `Update`'s unconditional invalid/PI writes, then perform the fade-out/clamp/XMVectorSin anticipation update before trajectory and incline. Read the fade-out parameter from the already published camera fields and retain typed failures. Keep `PendingGrindDetection` for the genuinely active, non-grinding `FindBestGrindCandidate` branch until the same-world BoxTest and candidate filter are implemented. An explicit test should assert the detector remains inactive in this selected corpus at the frame-3 boundary, and a separate active-detector test should still return the typed pending error after the source-prefix writes. Do not force `kbEnableGrindDetector=0`, set the detector inactive for convenience, skip the anticipation call, or replay a failed partial frame.

The native code still constructs a local frustum matrix before calling the detector even if its inactive branch will not query. An implementation may need to preserve its numeric boundary and source reads to claim exact function order; a bounded inactive continuation can state that pure matrix scratch is not yet parity-certified. Any later claim of complete active grind detection needs the frustum math, existing shared query, candidate ranking and camera graph/activity producer, not just the inactive path.
