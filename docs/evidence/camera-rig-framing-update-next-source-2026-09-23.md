# Rig framing update after composed target quaternion

Read-only IDA source audit, 2026-09-23. This packet proposes no Rust edit and claims no runtime or hardware-bit validation. Confidence is **high** for the caller, fields, control flow, and scalar instruction order below; **medium** for the final VMX matrix formula until its permutes and the arbitrary-axis rotation are checked against a reference trace.

## Caller and ownership

`Iris::CameraMan::UpdateRig` `82e47e68` is the only code xref to `Iris::Rig::DoFramingUpdate` `82e42ee0` (size `0x740`), at `82e48490`. The caller first stores `FrameComposer::DoFraming`'s quaternion at Rig `+0x80` (`82e48488`) and calls `DoFramingUpdate(dT, shotEditor)` (`82e48490`). Caller `r20` was copied from incoming `r6` at `82e47e94`, then moved to callee `r5` at `82e48480`; the callee copies `r5` to `r28` at `82e42f30` and tests it at `82e4346c`. IDA's pseudocode has an extraneous `a4` argument; the disassembly shows the matrix bypass is governed by that third C++ argument, `shotEditor`. The separate `retryWhilstPositioning` argument (`r7` in `UpdateRig`) is not this switch.

The callee owns Rig target quaternion `+0x80`, pitch and yaw tracker pointers `+0xb0/+0xb4`, GameCameraParameters pointer `+0xc4`, humanized 3-column matrix `+0x40..+0x6f`, tilt and pan smoothing `+0x1a8/+0x1a4`, roll `+0x1b0`, framing mirror `+0x17c`, initialization time `+0x160`, and flags `+0x1d8`. Its only call-site is the full camera update. After it returns, `UpdateRig` copies FrameComposer reference `+0x30` into CameraMan `+0xc0`, framing X/Y, rig/positioner matrix data, velocity and angular velocity, applies ShakeEffect unless retry, and selects the resulting CameraMan frame. Thus completion of the Rig method alone leaves another caller-owned frame-publication continuation.

## Ordered Rig behavior

1. Convert the target quaternion to a basis, then call `Math::EulerXYZFromNormalizedVector` on its forward direction with roll zero (`82e42f34..82e42fc8`). A sign adjustment on the resulting Euler vector precedes angle normalization (`82e42fd8..82e42ff4`). The exact VMX lane permutation deserves operand-level review before asserting bit parity. Normalize target yaw minus retained yaw tracker output (`82e42ff4..82e43008`), then take the normalized absolute value through source branches and calls (`82e43010..82e43050`).
2. Fetch live `pan_umbra` and `pan_penumbra` at parameter `+0x320/+0x324`, multiply each by the source float `0.017453292`, then call `Rig::EvaluateUmbra82e3cc58` (`82e43070..82e43090`). Raw `FCMPU`/`BLT` at `82e3cc78/7c` and `82e3cca4/a8` require ordered less-than: return 1 if `value < umbra`; otherwise interpolate `1 - normalize(value-umbra)/normalize(penumbra-umbra)` only if `value < penumbra`; otherwise return 0. Unordered/NaN value returns 0. Pass the result to `Sk8::PointGraphEval::Evaluate824e2c40` with **eight** `pan_smoothing_curve` samples at parameter `+0x180/+0x1a0` (`82e43094..82e430a0`).
3. Compute `pan_floor = 1 - (1-pan_min_smoothing)^2` using native `FNMSUBS`; only when current `pan_smoothing >= pan_floor`, replace the local pan value with `(current-pan_floor)*curve + pan_floor` (`82e430ac..82e430cc`). Set the local pan smoothing to 1 if it is at least 1; otherwise clamp it to at most float `0.9` with `FSEL`. Independently clamp Rig `tilt_smoothing` to 1 or at most `0.9` (`82e430d0..82e43110`). The local pan value is not stored back to Rig.
4. If Rig flag `0x08` is set or `initialization_time > 0`, set pitch and yaw trackers' input and output to separately normalized target Euler pitch/yaw, zero each velocity and acceleration, and clear flag `0x08` (`82e43114..82e43188`). Pitch tracker work is conditional on Rig flag `0x40` (`82e4318c..82e43300`); yaw tracker work is unconditional (`82e43300..82e43458`). This flag is therefore a real branch, not a generic pitch-enable option to elide.
5. Pitch tracker: live `kbPitchSpeedClamp` controls speed parameter at tracker `+0x24` (parameter tilt speed `+0x334` times radians factor, else `f32::MAX`); `kbPitchAccClamp` is sampled **twice** for acceleration min and max at tracker `+0x28/+0x2c` from tilt params `+0x338/+0x344`, each else `f32::MAX`. If clamped tilt smoothing is 1, set both smoothing endpoints to 1. Otherwise sample `kbPitchSmoothing` separately for min and max: enabled min is `min(tilt_smoothing, tilt_smoothing_min parameter +0x33c)` by `FSEL`, enabled max is `tilt_smoothing`; disabled values are zero. Write delta umbra and penumbra from tilt params `+0x348/+0x34c` times radians factor, then call the existing angle Tracker Update with normalized target pitch and caller `dT` (`82e43198..82e432fc`).
6. Yaw tracker uses parallel but distinct live `kbYawSpeedClamp`, `kbYawAccClamp` sampled twice, and `kbYawSmoothing` sampled twice. Its parameter values are pan speed `+0x350`, acceleration min/max `+0x354/+0x358`, smoothing min `+0x32c`, delta umbra/penumbra `+0x35c/+0x360`; all angle/clamp values receive the same radians factor. The endpoints use local pan smoothing. Then call existing angle Tracker Update with normalized target yaw and `dT` (`82e43300..82e43458`).
7. If `shotEditor` is true, make matrix Euler input from the target Euler X/Y and zero Z (`82e4346c..82e434a4`); otherwise use retained pitch/yaw tracker **output** X/Y and zero Z (`82e434a8..82e434d4`). Call `XMVectorSinCos` for X, Y, and **zero Z** in that order (`82e434d8..82e43504`); construct the three Rig humanized matrix columns with VMX arithmetic (`82e43508..82e435c4`). Then compute roll angle `rig.roll * rig.framing_mirror` (`82e435c8..82e435d4`), call `Math::RotateAroundArbitraryAxis` about the newly formed Z axis (`82e435e4`), and overwrite all three humanized columns from its result (`82e435e8..82e435fc`). The helper's exact general-matrix graph and source W lanes still need validation.

The six framing cvars are absent from the current `InputCvarReferences` definitions and camera cvar wrappers. IDA dynamic initializers `82fa2fe8`, `82fa3038`, `82fa3088`, `82fa30d8`, `82fa3128`, `82fa3178` register them in `Camera_Dynamics` with startup booleans respectively **true, false, true, true, false, true**. They cannot be replaced by constant defaults because the routine samples linked values every update.

Keep `MissingParameter`, `Cvar`, `Numeric`, and `AngleTracker` failures explicit. Reuse the `Math::RotateAroundArbitraryAxis` research in `skeleton_normal_displacement.rs`, but its current private helper is specialized to an identity input and does not directly implement this Rig call.

After Rig publication, advance to an explicit **caller-owned** stop before CameraMan frame reference/matrix/velocity/shake publication (`82e48494..82e48858`); do not report the first camera frame as complete merely because this method returns. The current Rust `try_compose_frame(dt)` has no `shotEditor` or cvar argument, so its owner needs that narrow call signature threaded from `try_update_rig_prefix`. Also verify the caller's null ShotManager fallback (`82e4846c..82e48474`) against current Rust: it stores the global vector in Rig `+0x80` before the same framing call, whereas the current Rust composition path always accesses both shots.

Focused verification: assert startup cvar defaults and live overrides; test instant initialization and one subsequent tracked update with authored camera parameters; assert pitch flag `0x40` skip versus yaw continuation; test `shotEditor` direct-angle matrix versus tracked-angle matrix; test nonzero roll/mirror and zero-Z trigonometric call ordering.
