Read-only audit of registered selected-session and corpus callers, with direct IDA PPC checks of spawn, registration status, and PROXY-before-BAM order. This is a policy boundary for a **controlled PC skating test**, not a native whole-boot recipe. No registered source or Cargo command was changed.

The smallest honest app path is an **explicit opt-in controlled first-test profile** that names each fixture choice, uses the existing retained `SelectedSession` and Windows pad/Juice adapters, derives spawn/gravity/camera name from original data where available, and polls one selected frame at a declared fixed cadence. The profile must report `Pending` or a typed error at the first missing owner instead of manufacturing success. It may show a simulation/camera diagnostic even while registration remains pending; it cannot report native boot parity or a rendered skater solely from the selected frame's palette.

There are two different hard gaps. For **native-order boot**, enabled PROXY load and activation are required before BAM (`0x8273b474`, `0x8273b4e0`, `0x8273b524`); no retained production PROXY load/activation owner supplies those callbacks or feeds the same manager into BAM high-collection effects (`proxy-first-skater-root-owner-gap-2026-09-23.md`). Independently, native player admission still lacks the command-3 sender timing and Actor-backed presentation entity/peer status path. The controlled test can explicitly bypass those native schedules; it still needs a real app invocation and OS/window/render wiring, plus an original-data cross-owner run, before anyone can claim a runnable PC skating test.
