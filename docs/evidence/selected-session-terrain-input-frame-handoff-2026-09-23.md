# Selected session terrain, input and queued-frame handoff — 2026-09-23

This is a bounded integration sketch after independent review of the registered, non-public boot owner. `SelectedSessionTerrain`, `SelectedProductionInputOwner`, and `SelectedSessionFrame` are registered in `lib.rs`; their existing constructors and consumers should be composed, not copied into a new corpus-style constructor. The boot owner still has an unresolved native spawn-message schedule and no registration status producer. A host-selected first-test spawn can advance its controlled path, but no runnable-session claim follows from the handoff below.

## Same-owner sequence

1. After the world exists, retain one `SelectedTerrainSource<Effects>` using the boot world's exact `Arc<Mutex<PhysicalAssemblyWorld>>`, the asset owner's exact `Arc<MountSet>` and cvars, plus host-supplied `WorldStreamCatalog`, `WorldStreamSpec`, `WorldStreamEffects`, and `EnvironmentUnlockSeed`. Retain one `SelectedSessionTerrain<Effects>` with an explicit collection ID, DMO parallel answer and arena userdata. `try_poll_stream` must finish before `try_request`; `try_request` installs world-line queries and retains the resident request; `try_poll` owns the one resident decode and normal-arena registration. Its `ground_pool_for(&same_world_arc)` checks world identity and completion. This describes intended world-init/source ownership, **not** a proven terrain-before-pair schedule: the mounted camera corpus builds the physical pair before streaming/registering terrain. The original-data terrain test verifies 21 plans and a 128-capacity pool for its explicit BAM policy; those values are evidence, not constructor defaults.
2. After the boot owner's same Actor/physical pair, call `SelectedPlayerStartupOwners::try_ensure_player_graph_owners`. With the completed terrain's `terrain_for(&same_world_arc)` and `stream().bounds`, call the existing `SelectedTerrainStartup::try_camera_inputs` using the held world, exact selected player owners, and host-supplied camera-set name. Pass that capability to the **already registered** local manager camera observer with `try_capture_selected_camera`, then call `try_admit_first_actor` against the world's existing `SimulationEntityRoster`. This preserves the selected corpus order: physical pair, graph cache/camera capture, roster publication, graph enable/load, local-change observer. Capture is not a new camera or graph owner. Native camera Activity and full view/projection remain pending; the selected tick only performs its bounded camera prefix.
3. Move the boot `SelectedInputBootstrap<C>` into `try_bind_player` with the exact `SelectedPlayerStartupOwners` and host-supplied `SelectedSimCommandQueue` and `SimulationCommandRandom`. It checks `Arc::ptr_eq` on the single `input.cfg` map and captures the backend controller. On failure its `ProductionInputBindFailure<C>` returns bootstrap, queue and RNG together; store that failure in the session instead of dropping those owners. On success retain `SelectedProductionInputOwner<C>`. Its `poll_and_cache` does hardware poll, SIM cache, PRES cache. `try_preupdate_enqueue` takes the same actual `PlayerLoaderSlot`, real focus/can-simulate and `PhysicalGameInfo`; it may return false without queued work. `queued_tick_input()` lends the owned queue and RNG for exactly one frame. The host must supply the source reset/seed/unlock policy before command consumption; no corpus remap, offline seed or controller index is a default.
4. Retain one `SelectedPlayerTick`, the selected player's existing `GameInputFrameSession<ActorIdentity>`, its same `ActorPhysicalAnimationInputs`, the pair's board/skeleton handles, the world, and one `SelectedPresentationRuntime::try_new` built from the selected player's actual retained `recipe_load.scene()` and presentation startup. Require explicit `SelectedPresentationPolicy` (LOD, buffer capacities, provider and root-W transport), original Vault gravity application, `Actor::try_construct_physics_auxiliary`, live feedback, sync and recognizer services before a tick. For each queued frame, borrow the completed terrain ground pool, bound input owner queue/RNG, and those disjoint retained fields to construct the existing borrowed `SelectedSessionFrame`. Build `SelectedTickRequest` from host dt/LOD/physics/grind policies and invoke `try_step_queued`. A zero command mask returns `NoCommands` before Actor/physics/presentation; a completed tick publishes the same-frame palette/materials through the existing runtime. Errors leave previous world/Actor/animation writes in their owners and must not be replayed as a blank frame.

The session owner needs separate `Option` slots for terrain, bound input, selected tick and presentation runtime (or an equivalent nested retained owner); the world and player stay in their existing slots. Borrow these fields separately for each frame, dropping the world mutex guard before any later callback that would lock the same world. The input bind's consumed bootstrap requires a retained failure slot because its error carries all moved owners. The current `SelectedSessionPlayerStartup::try_new_inner` still loses partial player/source on an internal error. On successful construction it now retains the exact Register request returned by the split preparation method; this is not completion status.

Before the newly applied combined corpus patch, queued input branches used `native_roster=false`, while the native-roster/camera branch used immediate input. A **production cross-owner** integration test must still use one selected mounted Actor with `native_roster=true`, the exact bound `SelectedProductionInputOwner` map/Juice/queue/RNG, completed `SelectedSessionTerrain`, same local camera observer, and `SelectedSessionFrame::try_step_queued` in one run. It should first verify an empty queued mask skips Actor/physics/presentation, then verify a real queued mask reaches the selected camera prefix and same-frame palette/material publication. Separate corpus fixture passes cannot establish that production cross-owner borrow, order or identity.

The independently reviewed corpus patch at `artifacts/selected-queued-native-roster-camera-test-20260923.patch` is now applied and root is running its original-data test. It covers a **narrower first combination** using the existing explicit queued pad/remap fixture and `RetainedGrindCorpus`. It passes the already retained camera residency into `check_queued`, so `check_mode` uses that same ground pool and does not invoke its fallback terrain mount. It does **not** bind `SelectedProductionInputOwner` or use `SelectedSessionTerrain`; it cannot prove production input/terrain identity.

## Concrete unresolved gates

- Native `cMsgSpawnPlayer` sender timing relative to the Register request; the `PlayerUI::ReceiveSpawnMsg` location-spawner readiness check is constant true and does not establish that timing.
- Ordinary presentation recipe-map notification and Actor submit/restore to a live `SkaterPresEntity`, then the full 64-bit peer match in `PresCharacterManager::Update` and simulation status delivery. The existing selected presentation startup/runtime do not supply this registration service.
- Source-owned terrain collection/spatial focus and Environment unlock seed, DMO parallel answer, arena userdata, gravity/reset seed, native camera Activity and rendering/view projection. The current terrain test supplies explicit corpus policies for these.
- A production app session caller providing pad/transport, stream effects, numeric and timing policies, camera-set name, collision/feedback and recognizer services. The mounted corpus's fixture `Platform`, remap and scripted queue are not substitutes.

No registered file was edited and no Cargo command was run for this sketch. It is intended to guide one fallible retained integration from the registered boot prefix; it does not duplicate constructors or assert native whole-frame parity.
