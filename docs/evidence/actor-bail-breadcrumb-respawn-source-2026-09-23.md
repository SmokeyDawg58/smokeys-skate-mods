# Automatic bail respawn: Actor breadcrumb source and reset publisher

The 300-frame local raw bail replay enters `PhysState_Teleporting` 702 at step 257. On its first Update with Processed `+0x8c4` bit 4 clear, native `PhysState_Teleporting::Update` `0x82d86940..b8` invokes `Skeleton::TeleportSomewhereAppropriate` `0x82b3b860..70`, which calls the bound Actor query. It does **not** immediately remount Ground. The later Update sees a published external reset through Processed bit 4 and copies all four matrix columns, on-board bit and ready/data-acquired flags.

`Actor::TeleportSomewhereAppropriate` `0x825f0e18..0x825f0f50` first checks whether the Actor has an AI controller. With one it tries `AIController::GetAppropriateRespawnTransform`; ambient AI can instead be unspawned. The selected local skater's retained `ActorPhysicsAuxiliary::ai_controller` is `None`, so the local path calls `BreadCrumbManager::GetSuggestedBreadCrumb` `0x82ce3308`, records the suggested foot-forward value, then calls Actor `Teleport` with the suggested transform and inverse of its off-board byte. The camera's `CameraBreadcrumbs` is a different owner and cannot supply this return point.

The Actor creates its skater `BreadCrumbManager` at `0x825ff438`, passing the Actor's original spawn matrix and world/query services. `BreadCrumbManager::BreadCrumbManager` `0x82ce3520` allocates its `Implementation`, whose constructor `0x82ce33b8..0x82ce3510` initializes a 33-entry ring, sets spawn/override transforms, binds the **class `0x12b64c0e804b0853` and default collection `0xd7edbd362d7d2152`**, and drops an initial breadcrumb from the passed spawn matrix. The earlier one-key reading was an IDA pseudocode register-recovery error; PPC instructions at `0x82ce3454..348c` establish both full 64-bit keys. The class key stated here was corrected on 2026-09-24 after comparing `insrdi r3,r22,32,0` with the mounted `skater.vlt` class export; see [the gate-attribute audit](bail-breadcrumb-gate-attributes-2026-09-24.md). `DropBreadCrumb` `0x82ce1fd0` samples `Actor::GetFootForwardWithFakie` `0x825ed560`, copies the four matrix columns and the off-board bit, then calls ring `push_back` `0x82ce1e30`. Push advances `mEnd` modulo 33; if it meets `mBegin`, it advances `mBegin`, preserving at most 32 live entries. `Implementation::Update` `0x82ce2230` can drop more breadcrumbs from `Actor::CalcRespawnTransform` after the reset-frame, distance, physics, collision and navmesh gates. Its wrapper `0x82ce2880` is called from `SkaterManager::PostUpdate` at `0x825f8bf8`; a pre-physics or camera-frame update would be out of order. `GetSuggestedBreadCrumb` `0x82ce3060` uses an override when set; otherwise `PopSuggestedRespawnPosition` `0x82ce2ef8` first tests the wipeout spot, then pops a valid ring breadcrumb, then uses the last resort. `GetWipeoutSpotBreadCrumb` `0x82ce1cb8` checks collision, navmesh and living-world constraints; `PopBreadCrumb` `0x82ce2d80` checks living-world constraints and erases the chosen ring entry. The precise spawn chosen in this test depends on those gates and cannot be inferred solely from the initial spawn matrix.

`Actor::Teleport` `0x825ed1c8..0x825ed220` is an independent publication step. It increments `mTeleportCount`, copies all four 16-byte transform columns into the existing `mExternalPlayerReset`, writes on-board, ORs Actor flag `0x20000000`, and zeroes `mTimeSinceFadeInStarted`. Rust already retained the exact destinations: `ActorConstructorPrefix::external_player_reset`, `input_generation_flags`, and `ActorInitialFields`. `actor_teleport.rs::try_publish_teleport` now performs only those writes for a caller-supplied transform; it does not fabricate a breadcrumb or claim an automatic bail recovery. The Actor animation physics suffix already transfers the retained reset and flag into `AnimOutPhysIn`.

Rust now retains a distinct Actor skater breadcrumb owner with the source ring size, initial spawn seed, copied matrix/foot/off-board fields, Vault instance keys, newest-to-oldest ring scan, and source `erase` direction. The inactive override retains the constructor's spawn matrix, RIGHT foot enum and false off-board byte separately from the active flag. The selector keeps override, wipeout spot, valid ring, last resort order. It requires caller-supplied collision, navmesh and living-world gate answers through `BreadCrumbSelectionSource`; no selected-session implementation currently supplies those answers. `ActorConstruction::try_construct_breadcrumbs_from_animation` now mounts the owner in the selected physical continuation immediately after the `PhysicalPlayerHiLOD` constructor returns. It samples the published animation's `natural_stance` and `relative_stance` for `SkaterAnim::GetFootForward` `0x82cb78a0`, then its known riding-fakie bit for `SkaterAnim::GetIsRidingFakie` `0x82cb7530`, following `Actor::GetFootForwardWithFakie` `0x825ed560`. The GetFootForward PPC loads at ISkaterAnim+`0xe58` and +`0xe60` resolve to SkaterAnim+`0x6138` and +`0x6140`, the two retained stance fields. The mount remains pending combined-build validation. Next connect the concrete services to `GetSuggestedBreadCrumb`, then call the Actor publisher, permit the following processed input to carry bit 4, and execute Teleporting's ready Update/Fill and `TeleportPlayerNow` remount in native order. A direct spawn-matrix reset would skip original selection and is not supported by this evidence.

Independent IDA review confirmed the publisher's retained fields and order. The
native teleport counter wraps as a 32-bit word; Rust now uses `wrapping_add`,
and its focused test covers the wrap, both on-board values, all 16 matrix
lanes, fade reset, and flag publication.

## Constructor service identities (2026-09-24 audit)

At `Actor::Actor` `0x825ff350..0x825ff438`, the `IPhysicalWorldServices`, `INetworkGameCollisionQuery`, and `INetworkGameQuery` arguments all refer to interfaces of the same Simulation singleton. The Actor obtains `mLivingMan` from that Simulation workspace and obtains `MeshStore` through `LW::Man::GetMeshMan()->GetMeshStore()`. `BreadCrumbManager::Implementation` stores these pointers in order at `0x82ce3418..0x82ce3428`. These are borrowed constructor references, not five separately allocated services.

Live selected pre-solve already holds the World mutex, so `try_query_owners_in_world` checks the weak Simulation identity against that borrowed World and uses the same LivingWorld/MeshStore identity validation as the outside-lock `try_query_owners`. Callers must use the in-guard method in pre-solve to avoid recursively locking World.

The selected host retains one `SelectedSessionWorldStartup.world` Arc for the Simulation projection, one `world.grind_services.living_world()` Arc for its LivingWorld occurrence, and one `MeshMan.store` Arc returned by that LivingWorld's `try_mesh_store()`. `SelectedSessionTerrain` already captures an Arc clone of the same MeshStore before arena registration. `PhysicalAssemblyWorld::physical_world_services()` represents the selected World's physical collection, **not** the native Simulation `IPhysicalWorldServices` interface; its `GameInfo` is the retained source for the network flag. `ActorBreadCrumbConstructorOwners` now captures weak references to the existing World/LivingWorld/MeshStore immediately after the selected physical constructor returns. `try_query_owners` upgrades them and checks the World→LivingWorld and LivingWorld→MeshStore pointer identities before the caller locks World for a reached query. The three native Simulation interfaces share the one weak World identity; no duplicate World or network flag is allocated. The selector has not yet consumed the verified bundle. The network collision path remains explicit and unsupported. This does not claim complete `LivingWorld::Manager::Init` or global `InitLWMan` publication.

## PostUpdate producer (2026-09-24 audit)

`Simulation::SimUpdate2` calls `SkaterManager::PostUpdate` at `0x8289fd3c`, after the second `Predictor::Update` `0x8289fce8` and `StepSelector::Update` `0x8289fd00`. The manager's first roster loop at `0x825f8ba4..8c08` calls `GetFlags` on each Actor; only `(flags & updateMask) != 0` and a null Actor `mAIController` reach `BreadCrumbManager::Update` at `0x825f8bf8`. The selected live tick already has a post-solve, camera, then second predictor subsequence; any selected breadcrumb projection belongs after that predictor, under the actual Actor flag/mask and AI gates.

`BreadCrumbManager::Implementation::Update` `0x82ce2230` obtains the Actor's `PhysOut`, asserts it and `PhysOut::mSkeleton` exist, then at `0x82ce22c0..22c4` copies **all 16 bytes** of `PhysOut_Skeleton::mSkeletonHipsPos` (Skeleton `+0x40`) into `Implementation::mLastKnownActorPosition` (`+0x120`). This copy precedes and does not depend on the `mFramesSinceReset >= kMinTicksAfterResetForBreadCrumb` test at `0x82ce22d8`; the cvar initializer `0x82f89550` supplies default `120`. The existing Rust `PhysicalPlayerPhysOut::try_skeleton_output().skeleton_hips_pos` retains that exact source vector. A root matrix translation, deck position, or camera hips projection would read a different owner or field.

The `mLastKnownOrientation` matrix (`+0xe0`) is **not** updated by that unconditional copy. When the outer frame/distance gates permit `_TestForPhysicsConstraints` `0x82ce1880`, its physics-state `100` or `104` path calls `Actor::CalcRespawnTransform` at `0x82ce18d8` and copies all four matrix columns into `mLastKnownOrientation` at `0x82ce18ec..190c`, even if a later state-count, grind, surface, collision, or navmesh gate rejects dropping a breadcrumb. The source-backed retained PhysOut Calc leaf, velocity cvar, reset-tick cvar and outer distance gate are documented in [the Ground leaf audit](actor-calc-respawn-transform-ground-leaf-2026-09-24.md).

`ActorConstruction::try_post_update_breadcrumb_hips` reproduces the first roster flag/AI gates, obtains the same retained physical output, and copies `skeleton_hips_pos` into the Actor breadcrumb manager. The selected flags-3 tick calls it after the second predictor update. It returns a typed error if an eligible Actor is missing its breadcrumb owner or skeleton output, rather than substituting a constructor or camera value. After the native reset-tick and newest-ring distance gates, reached Ground100/104 refreshes orientation through the same retained output and returns `GroundPhysicsConstraintsPending` after that store. State-count, hang, surface, the outer second Calc, collision/navmesh and another ring drop are not yet claimed. The current orientation can be observed after its source-reached publication even if those later gates remain pending.

Read-only call-site review: the source manager loop uses only `updateMask` for the first breadcrumb loop; `submitMask` is not tested there. `Actor::Actor` stores the supplied `SimulationFlags` in `mFlags` at `0x825fe914`, matching the retained `ActorInitialFields::flags`. The selected tick admits queued mask `3` before its flags-3 physical route, so passing `3` to the gated copy preserves this reached mask. Native `SimUpdate2` also runs `StepSelector::Update` at `0x8289fd00` between the second predictor and `PostUpdate`; that independent call is not part of this bounded selected tick. The placement preserves the relative hips producer order but does not certify the full `SimUpdate2` manager schedule.
