# OffBoard controller start at the mounted raw-Y boundary

The mounted raw-Y replay in `artifacts/raw-y-action88-breadcrumb-live-mount-2026-09-24.log` completes frame 58 in physical `GroundAnimation103`, Action9, Motion101. At frame 59 the physical selector requests OffBoard500, and the transition stops before publishing transition fields at `PendingStartController`. The existing `try_enter_physics_state` deliberately refused this branch; its Stop path is separate and remains unchanged.

IDA debug symbols and decompilation:

- `Sk8::Physics::SkateboardController::EnterNewPhysicsState` `0x82dd1d50`: states 500 through 504 call `StartController` at `0x82dd1d60`; other IDs call `StopController` at `0x82dd1d64`.
- `Sk8::Physics::SkateboardController::StartController` `0x82dd1678`: if `mSystemOn` is set, returns without reading processed input. Otherwise reads `ProcessedPhysIn+0x8d0` at `0x82dd16a4`. Either bit `0x800` or `0x400` selects `SKATEBOARD_FREE` (2), calling `LetGoOfSkateboard` at `0x82dd16e8` only if state differs, then storing 2 at `0x82dd16f0`. With both bits clear, state differing from `SKATEBOARD_ANIMATED` (1) calls `HoldSkateboard` at `0x82dd16cc`, then stores 1 at `0x82dd16d0`. Both branches store `mSystemOn=1` last at `0x82dd16f4`.
- `HoldSkateboard` `0x82dcc738`: chooses the soft-hook cvar at `0x82dcc75c`, enables board animation, sets board Standard at `0x82dcc780`, enables collision volumes at `0x82dcc798`, asserts the hand sentinel equals 2 at `0x82dcc7a4`, reads processed `+0x8cc` at `0x82dcc7cc`, stores state 1 at `0x82dcc7d0`, stores hand `(~flags >> 3) & 1` at `0x82dcc7dc`, then calls `EnableHandDrive` at `0x82dcc7e0`.
- `EnableHandDrive` `0x82dcc618` reads linked hand-drive and strength/displacement cvars, updates the retained selected drive's angular and linear dynamics, and calls `UpdateDriveFrames`; it is not equivalent to a boolean store.
- `Skateboard::EnableBoardAnimation` `0x82b2a140` marks the board animated, writes the body linear drive type 2, spring `59.999996`, damping 0 and strength `3599.9995`, then calls `HookEnableAngularDriveSoft(1.0)`. The soft variant `0x82b2a188` marks animated and calls both soft hook drive setters. Neither enable path is present in the selected Rust board entry owner yet.

## Live Hold integration audit (2026-09-24)

`PhysicalAssemblyWorld::try_transition_pair_ground` enters the controller stage before publishing any transition fields. Its OffBoard500 dispatch still calls `try_enter_physics_state` and returns typed `PendingStartController`. This remains the correct live boundary for the mounted frame-59 raw-Y replay (processed `+0x8d0` free masks clear, controller state 0); no partial Hold effects were wired.

The reached Hold branch has three concrete live adapter gaps. The `SkateboardEntryState::try_enable_board_animation{,_soft}` leaves exist, as do board-owned `force_runtime.entry` and `hook_dynamics`, but the skater pool/world has no method to run those leaves on the same retained board. `try_set_board_standard` already performs its own `EnableCollisionVolumes`; Hold calls `EnableCollisionVolumes` again at `0x82dcc798`, and there is no separate live method for this second volume-flag sequence/revision. Finally, `EnableHandDrive` and `UpdateDriveFrames` both exist on the controller, but the former's frame callback receives only the hand value, so a live caller cannot invoke the latter on that same mutably borrowed controller without a source-ordered adapter or callback signature change. These are missing dispatch services, not missing arithmetic leaves. The completed `UpdateDriveFrames` method and rotated geometric test are documented in `skateboard-controller-drive-frames-2026-09-24.md` and await the parent-owned combined build. The unreached free/LetGo path remains typed pending.

## Reached Hold dispatch implementation

The gaps above were subsequently filled for the reached Hold branch. `physical_player_offboard_controller_start.rs` receives the already validated physical owner and executes `try_start_with` before any transition fields are published. It reads the actual processed `+8d0/+8cc` words at their callback sites. The board-animation dispatch uses the same retained `force_runtime.entry` and `hook_dynamics`; the hard path captures Body before setting animated, while the soft path sets animated before its first Body capture. The existing angular/linear soft leaves and linked cvars perform their own reads and numeric work. `SetStandard` is followed by a standalone second `EnableCollisionVolumes` on the same constructed board. The standard corpus now checks that this second call advances the volume revision even with enable bits already set and invalidates a previously refreshed collision publication.

The Start and HandDrive callbacks now receive the same mutably borrowed controller at the nested call sites, allowing `EnableHandDrive` to invoke `UpdateDriveFrames` on its retained frame slot after dynamics writes. Each of its three use-hand-drives gates rereads the linked cvar; the frame service reads Skeleton animation volume Part0 and selected Part3/7 from the registered pair. The scalar host numeric adapter supplies the existing reciprocal-square-root estimates for each lane. The free/LetGo branch remains explicit `PendingLetGo` and can still halt if future input reaches it. This code awaits the parent-owned combined build and mounted replay; the earlier audit paragraph records the state before this implementation.

The controller owner now has a callback-based `try_start_with` that preserves these Start and Hold store/branch orders, including the prefix after a failed hand-drive callback. The callbacks explicitly separate board preparation, processed `+0x8cc` read, drive enable, and LetGo. Unit tests cover active short circuit, free branch, Hold ordering, and a late drive failure. This is not yet mounted in `GroundAnimation103→OffBoard500`: board animation enable, soft-hook cvar, hand-drive dynamics/frames, and LetGo need source-backed live services. The mounted replay therefore still correctly stops at the original `PendingStartController` boundary. Both focused tests passed in `artifacts/start-controller-focused-2026-09-24.log`. After independent review, Rust repeats Start's state-1 store after Hold returns, matching `0x82dd16d0`.
