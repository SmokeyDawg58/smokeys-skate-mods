## First registered-file move: same world and local owner

`SelectedSessionWorldStartup::try_new` moves the `repeated_frames && native_roster` prefix from `physical_player_ground_startup_corpus.rs:128-185` into a fallible production constructor. It constructs one `PhysicalGameInfo` and `LocalBackendOwner`, samples the live ghost cvar, calls `PhysicalAssemblyWorld::try_new_selected_main`, initializes feedback/prediction/grab/debug/grind services in the same order, constructs the entity roster and local manager from that world/backend, registers a real queue7 with startup observers, resets local identity, initializes world services, samples the live parallel-pool cvar, and initializes the selected skater pool. It returns `Arc<Mutex<PhysicalAssemblyWorld>>` and an `Arc` of that world's same local manager. Ghost/parallel unsupported branches fail in the existing owners; no disabled values are chosen by the draft.

The first integration change should register **only this module**, then replace the selected repeated-frame/native-roster constructor branch in `check_schedule_policy`. Before the move, lines `128-185` construct `game_info`, backend, world, local manager and skater pool inline, then line `187` wraps `world` in `Arc<Mutex<_>>`. After the move, choose the shared owner once: `let shared = if repeated_frames && native_roster { SelectedSessionWorldStartup::try_new(&inputs.cvars, &inputs.vault).unwrap().world } else { /* existing inline constructor block through Arc::new(Mutex::new(world)) */ };`. Do not run the old block before or after the new selected branch; do not construct a second `PhysicalGameInfo`, backend or world. The historical nonroster and component fixture branches remain in that `else` block. The following `actor_player_startup_corpus::construct(&inputs.vault, &shared, inputs.spawn, &inputs.cvars, native_roster)` receives the same Arc and continues unchanged. A reviewer should first check the retained local `Arc` in `world.local_skater_identity` is the one the constructor returned, then run the mounted roster/three-frame and queued Kickflip gates. The draft does not include the registered test change; root owns integration and Cargo validation.

The typed failure sequence is explicit: `Cvar`/`Backend` while sampling ghost; `World`/`Feedback`/`Prediction`/`Grab`/`Overlay`/`Grind` during world initialization; `Queue`/`Observers`/`Local` after the entity/local pair is published; `Services`; then `Cvar`/`SkaterPool` during pool admission. Each error stops that boot attempt at its reached source stage. The draft returns no partially built world on error and does not claim native rollback or successful boot after a failed prefix; such recovery is a later policy decision. A true sampled ghost-enabled or parallel-pool branch is handed to the existing owner and may fail explicitly; the constructor does not silently force them false.

## Producer-to-consumer slice that can move now

The draft's `SelectedSessionFrame` borrows the already retained world, physical board/skeleton handles, same Actor, its physical animation and input session, selected player services, cvars/settings, presentation startup, and `SelectedPresentationRuntime`. It invokes `SelectedPlayerTick::try_step_queued` with the original `SelectedTickOwners`, preserving queued-mask admission and the existing input -> Actor -> pre-solve -> solve -> post-solve -> optional selected camera order (`selected_player_tick.rs:323-519`). `NoCommands` returns without presentation. On completion it calls `SelectedPresentationRuntime::try_update` with `ActorPresentationFrameSource` for that same Actor/services and the same retained body animation job source, then requires both `palette()` and `materials()` to succeed. The runtime itself checks presentation allocation identity and publishes only after its produced, decoded, corrected, finalized and packed palette phases (`skater_presentation_selected_runtime.rs:232-325`). Errors retain their stage; no failed phase is replayed or converted to a blank frame.

This is deliberately a **ready-owner frame seam**, not a constructor or public app API. Its caller must poll/cache/queue the actual pad before the request, bind materials from the finalized recipe, and retain the original scene, ground pool, camera and all world owners. The draft chooses host numeric implementations already used in the mounted corpus. It does not choose a timestep, root-W carrier, camera projection, remap policy, terrain collection, or renderer result.

## Why whole boot is not a bounded lift

`physical_player_ground_startup_corpus.rs:114-376` currently composes world, local identity, player startup, physical pair, normal-arena terrain, camera and tick with assertions and controlled first-test policy. `physical_player_assembly.rs:106-108` registers its corpus only under `#[cfg(test)]`. `physical_player_queued_input_corpus.rs:44-245` creates a fixture `Platform`/`CorpusRemap`; its native-disabled Juice branch (`juice_input_boot_corpus.rs`) explicitly overrides an original enabled setting with a fixture platform. Production must supply a real pad platform/remap boot answer and maintain SIM/PRES caches, selected command queue, random gate and focus before invoking the draft. The existing Windows XInput adapter lives in the app; there is no production app session caller.

The test-only RAW `rig_tpose` loader is **not** an input to the selected repeated-frame physical pair. Although `with_original_inputs` first loads it, the selected branch replaces those physical inputs before allocation at `physical_player_ground_startup_corpus.rs:188-193`. `SelectedPlayerStartupOwners::try_physical_inputs` uses `ActorPhysicalAnimationInputs::try_assembly_inputs` to read the same Actor's evaluated constructor bind pose, hierarchy and physics parameters (`selected_player_mounted_startup.rs:229-255`, `actor_physical_animation_inputs.rs:60-89`). A production boot should omit the controlled RAW loader rather than make it a default.

Other explicit boot inputs remain: fallible original Vault and startup.ini mounting (`attribute_runtime_corpus.rs:21-52`, `game_input_recognizer_corpus.rs:37-49` have assertion-based test drivers over production readers), an actual animation thread answer instead of the fixture `1` (`actor_player_startup_corpus.rs:48-65`), the source-selected spawn and default marquee policy, source-sampled world query/physics parameters and gravity, retained `SelectedWorldStream` plus `SelectedResidentStartup`/`SelectedTerrainStartup` with parked-grind exclusions, selected camera observer admission, a validated root-position-W transport policy, and material binding. Those must become typed, fallible boot inputs/outputs on a single retained owner. None is legitimately supplied by the draft.
