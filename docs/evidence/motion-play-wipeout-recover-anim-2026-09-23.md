## Recovery graph source and selection

`SkaterManager::Init` `0x825F1810` retrieves the original `Skater` playback data from the Simulation animation playback manager and passes it, with the animation attributes pool, to `SkaterAnimShared::Init` at `0x825F19B4`. `SkaterAnimShared::Init` `0x82CD48B0` invokes `InitWipeoutRecoverGraph` `0x82CCC340` at `0x82CD4A48`. The last name appears twice in source: disassembly loads separate literals at `0x822F278C` and `0x822F27A8`, each containing that same string. For each name it calls `PlaybackData::GetAnimTree` and `Animation::GetAttributes(..., 15)`, scans 64-byte attribute records in order for packed `Lean` and `Twist`, and initializes absent values to `0.0f` (`0x82CCC580..748`). It appends `(lean, twist, name)`; positive twist gets an additional `(lean, twist - 2*pi, name)`, negative twist an additional `(lean, twist + 2*pi, name)` (`0x82CCC74C..9CC`). The alias calculation uses a float constant represented by `6.2831855f` in the decompilation. Confidence: **exact** for branch and insertion order; original Xbox asset values have not been checked in this audit.

`Animation::GetAttributes` is vtable `+0x30`. For a direct clip, `Clip::GetAttributes` `0x82D80808` emits every attribute with `mBeginTime == -1.0f` before applying timed-attribute status masks. `Attribute::Init` `0x82D751A0` copies type-0 scalar bits from serialized value into the runtime record. Thus the native scan receives static `Lean` / `Twist` coordinates for clip leaves without interpolating a pose. This is exact for clip leaves, while other tree classes would require their own `GetAttributes` paths.

As a separate corpus check, the available PS3 `data\\anim/OnBoard.abin` has nine unique recovery names as direct type-2 clip records. Each has two static type-0 attributes in order, `lean` then `twist`, with begin/end both `-1.0f`. `OffBoard.abin` has no recovery names. OnBoard also has `W_RECOVERY_ONRIGHTHEAD_N_0_N`, which the audited source list does not request. This check confirms the direct-clip extraction path for that corpus; Xbox asset values and record types still need their own check. Do not hardcode these coordinates into runtime tuning.

`GetWipeoutRecoverAnim` `0x82C92738..78C` reads graph begin/end pointers at shared-owner `+0x8c/+0x90`, then scans 0x20-byte points in insertion order. A point stores lean at `+0`, twist at `+4`, and packed name at `+8`. It starts with maximum finite `f32`, computes `fsubs` lean difference then squared lean, `fsubs` twist difference, then `fmadds` twist squared plus lean squared. It replaces the winner only for strict `<` (`bge` skips equal and unordered), so the first tied point wins. It returns the selected name. An empty graph returns a pointer inside the empty begin buffer; there is no explicit empty guard in this leaf. Confidence: **exact** for selection and tie order, with the source's PPC fused multiply-add retained as a numerical detail.
