## Native first-use delivery

`GameModule::OneOffLoad` passes false to `cAssetStreamManager::EnableCollectionDefer` at `0x8273b084..08c`, which sets `mDeferCollectionReg` to zero at `0x82d54d00..064`. `NotifyCollectionPresReg` (`0x82d5c680`) still samples `kbEnableCollectionRegDefer`, the manager defer word, `forceImmediateReg`, and stream size; with the OneOffLoad defer word zero it takes the direct message path at `0x82d5c810`. This is the relevant boot branch; it does not license treating all runtime registration as nondeferred.

After the first parent request completes, `cLoadParentCollectionRequestCallback::OnComplete` (`0x82d5cac8`) enters `cAssetStreamManager::OnLoadParentComplete` (`0x82d5c978`). Only first use inserts parent count one and sends `NotifyCollectionSimReg` at `0x82d5ca78`, then `NotifyCollectionPresReg` at `0x82d5caa4`, with separate `cParentCollectionLoadedCallback` allocations. The Presentation notification performs `assman::cAssetStreamer::UpCollectionLoadedCount` **before** looking up stream type or queueing messages (`0x82d5c6ac`). It sends an activating `cMsgAssetPresRegCollection` for the parent (`0x82d5c840..84c`), skips the proxy-ID message because this parent call supplies the full invalid ID (`0x82d5c858..85c`), and sends a separate callback message afterward (`0x82d5c890..8b4`). The earlier Simulation notification owns its own distinct Up/notification. A fresh physical parent resident therefore goes from count one to three on first use.

`PresThreadMsgMan::ReceiveRegCollectionMsg` (`0x82780958`) checks the activating bit at `0x82780974`, resolves the **processed container asset** from `mContainerAssetRegistry` at `0x827809e4`, and walks its arena list in order. For each arena, `cAssetRefCounter<4096,2048>::AddAsset` at `0x82780a3c` gates first use; only its first-use result calls `Presentation::RegArena` at `0x82780ab0`. `RegArena` (`0x827f1430`) walks that arena's processed asset list forward. Kind 0 calls `Sk8::ShaderSystem::gTexMan.AddTexture` at `0x827f156c` with the processed wrapper's **aliased Texture identity** and its full 64-bit TOC ID. The parent PROXY corpus has 93 single-Texture arenas, so the observed parent route owes those product and manager effects before its queued callback is handled. The 93 count is a corpus observation, not a native constant.

`PresThreadMsgMan::ReceiveCallbackMsg` (`0x8277be10`) reads the queued callback pointer at message +0x18, skips null, and invokes its virtual `OnComplete` with the full ID at message +0x10 (`0x8277be1c..2c`). `cParentCollectionLoadedCallback::OnComplete` (`0x82d543e0`) only destroys that callback (`0x82d543f8`); it does **not** decrement the resident count. Thus callback completion acknowledges message processing after the parent `RegArena` walk, while the extra resident hold remains for the registration lifetime.

At last parent use, `UnloadParentComplete` (`0x82d59c60`) erases the zero use count, sends Simulation deregistration (`0x82d59d60`), then Presentation deregistration with a distinct `cParentCollectionUnloadedCallback` (`0x82d59d88`). The Presentation receiver `ReceiveDRegCollectionMsg` (`0x8277fff8`) walks the same container, calls `RemAsset` per arena, and on each last use calls `Presentation::DRegArena` (`0x82780128`), whose kind-0 arm removes the same aliased identity from shader `gTexMan` (`0x827f17bc`). The later deregistration callback invokes `cParentCollectionUnloadedCallback::OnComplete` (`0x82d581a0`), which finally calls `DownCollectionLoadedCount` at `0x82d581bc` and destroys itself. The Simulation deregistration callback releases its separate hold. The ordinary ancestor unload request accounts for the original resident use independently. Releasing the parent resident on its *load* callback would invalidate native registration lifetime.

## Existing Rust ownership and remaining implementation edge

`CollectionParentManager::LoadParentCollectionCallback::complete_with` already performs first-use resident Up, Simulation register, resident Up, Presentation register in that order; its unload path sends Simulation then Presentation deregistration at zero use. `CollectionResidentStreamer` owns the resident count and external hold release API. `OwnedResidentCollectionStorage<DecodedArenaAsset, ..>` retains the decoded parent assets; `OwnedResidentAssetsView::try_for_each` visits the same owner's assets in insertion order without escaping borrowed values. `ArenaRegistrationRefCounter` supplies the per-arena first/last-use decision. Reuse those owners. `SimulationResidentRegistry` is a different namespace and cannot publish the PROXY Presentation products. The unregistered shader texture table draft handles only table transitions, and the unregistered app upload client holds uploads without an alias/processed registry entry or root invoker.

The missing full effect is still the retained processed Presentation parent container and its 93 aliased kind-0 products, tied to the exact decoded arenas and real GPU objects, followed by `RegArena`/shader table mutation through the first-use gate. No current `CollectionParentEffects` production implementation can send and complete this path. A new callback counter, parser, or stand-alone manager would duplicate existing owners while acknowledging an absent effect. For that reason this packet proposes no unregistered patch. The bounded next implementation packet is one parent collection under an accepted retained PROXY catalog: construct exact products in authored order from the same resident asset allocations, register the parent through one result-bearing Presentation effect, prove the callback occurs after all kind-0 insertions, retain both subsystem holds, and on last use remove the same identities before the corresponding external Downs. It must stop on the first failed effect without fabricating a completed callback.
