# Reached SkeletonController collision mode 1

The mounted raw-Y replay entered physical OffBoard500 at frame 59 and stopped in `OffBoard::Enter` when `SetSkeletonCollisionState(4)` was translated by the already retained world-only controller to `SCS_COLLIDE_WITH_WORLD_ONLY_OFFBOARD` (1). The observed typed boundary was `OffBoardEntry(Collision(Controller(PendingCollisionMode(1))))`.

IDA `SkeletonController::EnterState` `0x82dd47a8` stores `mState` before its switch and calls `Skeleton::CollideWithWorldOnlyOffboard` at `0x82dd47e8` for state 1. The latter is `0x82b542c0..0x82b5436c`: it writes Assembly group 3, all Part userdata 3 in ascending order, calls `SkeletonBody::SetUpNoCollision(true)` at `0x82b54314`, writes `mSkeletonProxyVolumeEnabled=1`, tests root disable count, and if zero sets root Volume flag bit 0 and group 0. It then writes root Part userdata 3 again. `SetUpNoCollision` `0x82b47640` writes root group 4/flag clear/count 0, then clears each non-root flag and (because true) each count; the existing Rust `SkeletonRuntimeState::set_up_no_collision` already implements this, so it is reused without a second counter array.

The implementation adds a mode-1 callback to the existing `SkeletonControllerCollision` interface and dispatches it after the existing current-state store. The concrete callback on the retained `SkeletonNormalAssembly` composes its existing runtime state and post-physics proxy owner in native order. The same-pair bridge already invalidates collision publication before controller effects. A standard corpus continuation first checks that unsupported `Set(4)` retains current state 4, then starts world-only and checks controller state 1, group/userdata 3, proxy enabled, root flag/group, cleared non-root flags, and all zero counters. This is a controlled boundary test; the mounted replay and parent-owned Cargo check remain the authority for the live continuation.
