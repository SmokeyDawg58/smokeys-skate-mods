# PROXY single-Texture alias ownership audit (2026-09-23)

Read-only source and Rust owner audit. This note does not register a module or claim PROXY activation. Confidence is high for the native call and lifetime order, medium for a host representation of the Xbox fetch address. No Cargo command was run.

## Native producer and lifetime

`cProcessArenaAsset::InitializeFromMemoryDump82d54e40` fixes up the five-base `rw::Resource` arena through `Arena::FixupStart/Next`. `ProcessArena82d5fee0` checks its XST resource descriptors against the fixed-up arena (`82d5ff2c..6c`), finds the TOC, and takes the special path only when its count is one and the row type is Texture (`82d60038..58`). It allocates an empty `cArena` list (`82d60068..a4`) and reads the fixed-up source Texture pointer at `82d600a8`.

`GetParameters82bca610` samples the source texture (`82d600f8`). `GetAliasedParameters82bca760` samples it again, ORs alias flag bit 0, takes the fixed-up source fetch word masked by `0xfffff000` as its address, then adjusts width only if old and requested format bits-per-pixel differ (`82bca784..cc`). The caller passes the source format at `82d60104`, so the format ratio does not change observed width. `GetResourceDescriptor8282f7e0` requests lane 0 size `0x34`/alignment 4 and lanes 1–4 size zero/alignment 1 because the alias flag suppresses pixel lane 2 (`82d60114`). The Asset-category resource allocator vtable call at `82d60168` allocates that distinct 52-byte header. `Texture::Initialize82bcd0e8` clears it, calls `Xbox2SetTextureHeader`, and installs the alias address in fetch word 1, with mip address in fetch word 5 when applicable (`82bcd104..250`); it uses `params.address`, not newly allocated pixel data, for this branch.

`RegisterTexture82d5ea00` allocates a 28-byte `tGameTextureAsset` (`82d5ea34`), stores the new Texture at offset 0 (`ea78`), copies all five original arena resource bases into offsets +8..+24 (`ea8c..9c`), then **overwrites +8 with the new Texture pointer** (`eaa0`). The original lane-0 base is therefore not retained by this wrapper; lanes 1–4 remain copied. It adds Presentation kind 0 with the full TOC ID (`eabc`) and appends that registry asset to the processed list (`eac8`). After registration, `ProcessArena` copies the original five bases, selects only original lane 0, and calls the default allocator's virtual free at `82d601d0..82d60228`. The separate 52-byte alias header remains the registered product. The cArena's arena pointer at +0x10 stays null on this path; `ProcessArena` sets its local fixed-up arena pointer to null at `82d6022c` before common return.

At first Presentation registration, `RegArena827f155c..156c` passes the registered wrapper's Texture pointer and full ID to shader `gTexMan.AddTexture82e1b058`; `DRegArena827f17ac..17bc` passes the **same pointer and ID** to `RemTexture82e1b548`. On unprocess, `UnprocessArena82d59db0..e7c` takes its null-arena-pointer branch, removes the outer arena and child texture registry entries (`82d59dc4..e14`), invokes the asset-manager virtual operation (`82d59e18..2c`), deletes the separate Texture allocation (`82d59e30..3c`), deletes its wrapper (`82d59e40..44`), and releases the outer asset. The original lane-0 base was already freed during production. The virtual operation's exact semantic name is not established here; host code should not invent one. The original resource's remaining bases are not shown being freed in this branch and should stay under their existing streamed-resource owner until that owner's unload boundary is established.

## Existing Rust seam

`DecodedArenaAsset` retains the original five decoded resource buffers, XST descriptors, parsed RW4 arena, and full outer asset ID. `OwnedResidentCollectionStorage` is the persistent collection owner; its `OwnedResidentAssetsView::try_for_each` visits assets in insertion order without exporting a borrowed reference, and `weak_assets_in_order` can provide non-owning exact asset identities. `skate2_formats::material::Texture::parse` already exposes dimensions, format, mip data and six **serialized** fetch words. `own_texture_arena` resolves a TOC Texture to its GPU buffer object and decodes levels into `NativeTexture`. It copies data and loses the fixed-up fetch address and source allocation identity. A serialized fetch word or `NativeTexture` copy is not a valid replacement for the native aliased Texture pointer.

The smallest coherent host product is an owner-bound processed alias: full TOC ID and outer arena ID; the exact Texture and GPU-buffer dictionary/resource locators within the retained `DecodedArenaAsset`; the source Texture parameters and aliased descriptor; a distinct, stable allocated host texture/header identity; and a real render-service texture object made from the same source buffer. The host alias relation should be expressed as a typed source-resource locator, not an invented Xbox address. `GpuRenderer::upload_native_texture` already uploads decoded levels but returns app-owned `GpuTexture`; a future producer needs a concrete service boundary that owns this upload and binds its lifetime to the processed product. Its identity can then be passed to the unregistered generic shader table draft. The table must not be registered by itself, and a diagnostic ID or arbitrary integer is not a texture product.

Create the product once at decoded resident arena production, retain it alongside that **same** arena owner, and publish its kind-0 registry entry in TOC order. On Presentation first use, call `ArenaRegistrationRefCounter` before shader-table insertion; on last use remove by that exact identity before releasing the product and its render object. This preserves parent-first callback order and prevents a scene-level `NativeTexture` inventory from masquerading as registration. An isolated first packet can prove 93 parent products and table transitions with real decoded locators and a concrete render service, while reporting kind-0 only. Spatial kind-2 material binding and kind-10 Environment effects remain required for PROXY activation.
