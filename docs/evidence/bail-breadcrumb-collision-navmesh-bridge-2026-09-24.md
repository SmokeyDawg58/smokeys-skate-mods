## Collision gate and retained provider

`_TestForCollisionConstraints` `0x82ce19b0` makes a thin downward segment from candidate translation plus `(0, 0.1, 0)` to translation plus `(0, -10, 0)`. It gets the Actor's current island through `Entity::GetPhysicsIsland` (`0x825f1758`) and calls `PhysicsUtility::LineWorldCollisionTest` (`0x82e4a408`), which calls the island line query at fatness zero and copies hit position, normal, parameter and surface ID. The virtual slot `+0x44` used at `0x82e4a464` resolves in the concrete Island vtable (`0x820ffa10+0x44`) to `Island::LineCollisionTestWithVehicles` `0x827b2538`, a direct `World::LineCollisionTest` delegate. No hit rejects. The gate then reads two distinct breadcrumb attributes (PPC keys `0xadd032ca_cf6a1c15` and `0x8abe098d_3806d273`; corrected 64-bit half order in [the mounted attribute audit](bail-breadcrumb-gate-attributes-2026-09-24.md)) for its normal and vertical-distance comparisons. `_IsSurfaceOK` `0x82ce12d0` rejects extracted surface classes 5, 6, 8 and 9; the caller extracts `(surface_id >> 7) & 0x1f` at `0x82ce1b7c`. For the wipeout call, `IgnoreCapsuleTest` is false. It reads `CapsuleHeightForCollisionTest` and `CapsuleRadiusForCollisionTest`, then calls `IPhysicalWorldServices::LineCollisionTest` with a vertical line from **thin-line start plus radius** to **candidate translation plus capsule height**, with radius as fatness. The PPC vector sources at `0x82ce1bf4..1c20` resolve this previously ambiguous endpoint order. Any hit rejects. The concrete `Simulation::LineCollisionTest` `0x8289e5f0` calls `World::LineCollisionTest` `0x827ab338` with that fatness. Offline, successful collision checks return true at `0x82ce1c54`; the network collision query is a separate branch.

The retained selected `PhysicalAssemblyWorld::try_world_line_test` in `physical_player_world_line.rs` already delegates to the real `SimulationWorldLineQueries`, borrowing the registered `StaticGroundPool` from `SelectedSessionTerrain::ground_pool_for`. It accepts `CollisionLineInput` with fatness and returns position, normal, line parameter and surface ID. The same owner is already used by `SkaterManager::AdjustSpawnPosition` in `selected_session_public_facade.rs`; `CameraCollision` borrows it via `camera_line_services`. Thus both breadcrumb line queries can use this **same** World/ground/DMO owner, in native order, without another `CollisionScene` scan or pool. The `World::LineCollisionTest` wrapper's Acquire/Begin/Add/End/Sync/Get/Release order already exists. A bridge still needs the exact live breadcrumb attribute reads and comparison logic, current Actor-island route, cvar, and same-world terrain borrow at the respawn call. In particular, `CollisionScene::thin_segment_hits` has neither the retained island/batch route nor the capsule/fatness result and must not be substituted.

## Navmesh gate and retained provider

`_TestForNavMeshConstraints` `0x82ce14d0` accepts immediately when live `kbEnableNavMeshConstraints` is false (constructor default true at `0x82f895a8`) or the game is networked. Offline with the cvar true, it asks `MeshStore::GetMeshCell` for the candidate translation; an invalid cell accepts before reading the score attribute. A valid cell accepts only if `GetCellScore(cell, 0) < MaxNavMeshScoreForBreadCrumb`. `SelectedSessionTerrain` retains the same `Arc<MeshStore>` obtained from the constructed LivingWorld manager before arena registration. `MeshStore::try_get_cell` already implements the constructed empty-map invalid-cell result and preserves a pending tile-admission error. On a selected boot that completed registration without navmesh tile admission, this owner can answer the invalid-cell branch without a new mesh store or score lookup. The live cvar access is not yet present in `InputCvarReferences`, and a nonempty cell/score path remains unsupported.

Source-backed gate bridge: `actor_breadcrumb_collision_navmesh.rs` now borrows the retained World and registered ground for both collision lines; it reads the live breadcrumb attributes in native order, extracts the surface class, and fails explicitly on the unimplemented network collision branch. Its navmesh gate reads the cvar first, then network status, then the retained MeshStore's constructed empty-map invalid cell. `SelectedSessionTerrain::mesh_store_for` exposes that same captured owner only for its matching registered world. The selector still needs to connect these gates in collision → navmesh → LivingWorld order; the per-frame last-known breadcrumb update is not mounted. No live respawn success or Xenon numeric parity is claimed.
