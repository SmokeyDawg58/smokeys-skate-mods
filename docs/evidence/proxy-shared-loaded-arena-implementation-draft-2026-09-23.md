## Native source and implemented boundary

`cAssetManager::AddCompressedArenaAsset` (`0x82d63a10`) looks up `mLoadedAssetMap` by the full arena ID at `0x82d63a70..90`. A hit increments its physical loaded count and returns the existing processed asset (`0x82d63bc8..bd0`) without running the producer. A miss processes once and inserts that allocation with count one (`0x82d63abc..0x82d63bac`). `tLoadCollectionRequest::EntryComplete` (`0x82d5e530`) appends the returned pointer into each collection's ordered asset list. `DownLoadedCount` (`0x82d62edc..0x82d62fac`) frees at the final physical use. The per-arena Presentation `AddAsset`/`RemAsset` counter is separate. The complete proof and parent/activation callback order are in `proxy-native-loaded-asset-canonicalization-shared-owner-2026-09-23.md`.

The new generic `SharedLoadedArenaSessions<F, A>` wraps the existing `CollectionAssetBuilderSessionFactory`; its `SharedLoadedArenaBuilder` wraps each existing `CollectionAssetBuilder` call. It inspects `CollectionAssetBuildInput.asset_id` before invoking the source builder. A hit returns a non-cloneable `SharedLoadedArenaAsset<A>` handle to the same `Arc<A>` without parsing or uploading again. A miss invokes the existing producer once, checks that its full returned ID matches the request, and inserts it before returning a handle. The same `SharedLoadedArenaCache<A>` must be supplied to every collection session in one asset-manager domain. The cache lock serializes construction, giving one winner for simultaneous same-ID requests. Both the constructor and product destructor must not reenter this cache. The existing mounted producer, decompression driver, `DecodedArenaAssetBuilder`, `own_texture_arena`, and GPU uploader remain the only such implementations.

Each handle represents one physical collection membership, preserves the writer's insertion order, and decrements a dedicated `physical_uses` count on drop. At zero uses, both cache and occurrence strong references are dropped under the loaded-map mutex before the row is erased and the mutex is released. Thus a concurrent same-ID acquisition cannot construct a replacement until the old product's teardown completes, matching native `DownLoadedCount` ordering. A scoped `Weak<A>` identity can be derived from the occurrence by a future Presentation owner while its resident hold keeps the physical use alive. The handle itself is intentionally not `Clone`, so a second physical membership cannot bypass the count. Cache lookup, builder failure, identity mismatch, and count overflow return typed errors before publishing a new occurrence. A failed later builder leaves preceding collection assets and cache rows intact; the mounted driver latches that builder error, so a retry shown by the test is only a direct cache-level call, not an in-place mounted request retry. Internal drop invariants assert rather than silently underflow. Checked overflow is a safe-host deviation from the native raw increment at an unreachable practical count and needs review if exact wrap behavior matters.

The focused tests use actual `OwnedResidentCollectionStorage`: two distinct resident collections acquire one full-ID product, prove pointer equality and one construction, then release one collection while the shared product remains alive and release the second to free it exactly once. Another test distinguishes equal-low-word/different-high-word IDs. A failure-prefix test confirms a failed second construction leaves the first resident row and cache use intact, then exercises a direct cache-level retry. An identity-mismatch test confirms no map publication. A concurrent test blocks inside final product teardown, starts another same-ID acquisition, and verifies that replacement construction begins only after teardown is released.

## Integration limits

This is a **physical loaded-asset** seam, not a Presentation manager. It does not register `proxy_shader_texture_table_draft.rs`, dispatch kind 0/2/10, build a processed container registry, deliver a parent callback, release a resident hold, or increment PROXY activation. The earlier unregistered `Kind0ResidentBuilderSessions` accepts only the selected parent and therefore cannot itself process the 147 spatial collections; it can be wrapped for parent-only proof, but a unified processed arena product/factory must admit the observed parent/spatial branches before the cache is composed for enabled PROXY. The canonical allocation must contain kind-0 alias and decoded source together; its shared handle must be the value visited by the future unified Presentation owner. The existing `PresentationDmoArenaRegistrationAdapter` has its own bank-scoped counter and cannot serve as a second Presentation namespace.

Root's next integration review should verify the generic trait bounds against the current core crate, preserve one shared cache instance across all selected collection sessions, and run the focused tests plus mounted parent/spatial corpus. A real Presentation owner must use one first/last-use counter across admitted kinds, execute source-ordered effects before callback acknowledgement, and keep the separate resident holds until their unload callbacks. No success-only callback may be wired to this cache.
