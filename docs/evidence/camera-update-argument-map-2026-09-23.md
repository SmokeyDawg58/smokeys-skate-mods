# CameraMan Update argument provenance (2026-09-23)

The registered Rust currently names `CameraMan::try_update_prefix(dt, shot_editor: bool, retry: bool)`. That naming does not match the native ABI or the downstream consumers. Raw IDA/PDB: `CameraMan::Update82e48870` is mangled `UAAXMH_N`, so after `this` it accepts float `dT`, integer `cameraIndex` in `r5`, and bool `shotEditor` in `r6`. It saves `r5→r30` at `82e48890` and `r6→r29` at `82e4888c`. The `!r29` branch at `82e488cc..d4` gates mirror/free-cam/rig-option work; inside it, `r30==0` at `82e488dc..e0` gates DropPrediction. IDA's decompiler invents an extra `a5` and names the saved registers inconsistently; the mangled signature and raw moves/branches control this mapping.

At `82e4899c..bc`, `Update` fixes `r7=0`, forwards `r6=r29` and `r5=r30`, then calls `UpdateRig82e47e68` (`QAAXMH_N_N`: float, int, bool, bool). Thus `UpdateRig` receives `(cameraIndex, shotEditor, retryWhilstPositioning=false)` for this actual outer caller. `UpdateRig` saves `r5→r27` at `82e47e90`, `r6→r20` at `82e47e94`, and `r7→r22` at `82e47e98`; `r21` is a low-byte copy of `r20` at `82e47f84`. The `r21` flag skips `UpdateRigSubjectMatrix` at `82e47f8c..9c`, goes to `Rig::DoFramingUpdate` in `r5` at `82e48480..90`, and selects direct unshaken matrix publication at `82e48714..28`. `r20` also goes to `Rig::DoUpdate` `r6` at `82e48250`, where `82e47d40..64` selects instant angle trackers. The independent `r22` goes to `Rig::DoUpdate` `r7` and thence `Rig::UpdateCameraPositioner` `r6`, retaining the positioning retry. `r27` cameraIndex goes to ShotManager2::Update and Rig::DoUpdate `r5`.

The currently reached `ShotManager2::Update82e472c8` does not read its incoming `r5` cameraIndex (the prologue only retains `this` and `dT`). `Rig::UpdateCameraPositioner82e47808` passes its incoming `r5` onward to `LogicalCameraPositioner::Update82e47748`, which passes it to `PositionCamera82e47450`; the latter overwrites incoming `r4` before use, so cameraIndex does not affect that currently reached path. Preserve the integer argument provenance in the caller signature despite these observed nonreads.

Source-consistent retained signatures are `try_update_prefix(dt, camera_index: i32, shot_editor: bool, ...)`, and `try_update_rig_prefix(dt, camera_index: i32, shot_editor: bool, retry_positioning: bool, ...)`. The live selected camera invokes `try_update_prefix(dt, 0, false, ...)`, so this is a correctness correction for nonzero/editor paths and for later shake/publication wiring, not a claim of a new first-frame boundary. All branching currently named `retry` inside `try_update_rig_prefix` and `CameraRig::try_do_update_prefix` uses native `shotEditor` `r6`; only the separate third bool is native retry-positioning. `CameraMan::try_compose_frame` already takes a bool named `shot_editor`, but the current caller passes native `cameraIndex` there. A minimal patch must rethread these values without conflating them.

Confidence is high for register provenance, source branches and currently reached camera-index nonreads. Native offscreen/nonzero camera selection remains untested by the mounted first-skater trace. No registered file or Cargo command was changed by this audit.
