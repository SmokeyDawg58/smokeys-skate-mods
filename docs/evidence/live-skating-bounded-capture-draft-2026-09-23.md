# Bounded controlled skating capture draft — 2026-09-23

Unregistered review packet: `apps/skate2-pc/src/live_skating_bounded_draft_20260923.rs` and `artifacts/live-skating-bounded-capture-2026-09-23-draft.patch`. Only `apps/skate2-pc/src/live_skating_client.rs` changes on integration. No registered file or Cargo was edited by this author; `git apply --check` and draft `rustfmt --check` pass.

`--live-skating --live-frames N` passes `N` to the existing `RenderWindowOptions.frame_limit`, which counts successfully presented window frames, including boot-only static-map frames. `--live-capture PATH` requires `--live-frames` and uses the existing final-finite-frame GPU capture. A bounded run returns an explicit error if it exits without one completed selected simulation/presentation frame, so an early static-map capture cannot be reported as a skating success. The capture file may still exist after that error and must be read with the error status. Zero and malformed counts use the existing window/parse errors. No change is made to the diagnostic inspection command or the default unbounded live command.

Example: `SKATE2_GAME_ROOT=... skate2-pc --live-skating --live-frames 600 --live-capture artifacts/live-first-test.png`. The frame count is a host presentation bound, not a source frame or physics-tick count. A slow original-data boot may consume the bound; increase `N` if the run reports no completed selected frame. A successful image still uses the deliberately static original map and provisional selected camera, with enabled PROXY activation and restored presentation pending.

Backlog assessment: the current live client accumulates every elapsed redraw interval and processes all owed 1/60 host ticks before rendering. After a long minimize/debugger/GPU stall it can freeze while replaying many ticks with newly sampled pad state rather than the unavailable historical input. A future explicit host policy should pause the simulation clock after a declared stall threshold, log skipped wall time, and resume with one fresh tick; this is a usability choice and must not be labeled native timing parity. This draft does not change tick cadence or silently drop backlog.
