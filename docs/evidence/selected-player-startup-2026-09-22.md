# Retained selected-player startup extraction

The production composition is extracted from the existing fresh original-data
driver, without replacing the native constructors or their owners. Inputs remain
an already selected loader whose actual attribute application has run, the same
PlayerAttributeServices, initialized global animation and face owners, cvars,
mounted files, host spawn/flags, animation source and numeric service.

The sequence remains mounted input map; input pattern construction and reset;
selected input player; chase formation; Actor allocation and prefix/listener/graph
construction; the already reviewed same-player animation completion; graph owner
construction, enablement, Action load, Motion load. References remain the existing
constructor evidence: input manager 0x826e3308/0x826e2c20, Actor constructor and
animation constructor packets, and selected InitPlayer 0x826000b0.

The selected input player is taken from the supplied real loader index. No local
index literal, stance, character, tuning, neutral frame or registration completion
is produced. MountSet handles the same slash normalization as the old driver.

The mutable retained owner publishes each created Actor, map, formation and graph
owner before running its subsequent fallible stages. A failure leaves the current
partial state intact and prohibits rerunning the whole constructor. Graph load
results are retained as results; only the corpus requires both to be true.

The original-data wrapper retains its explicit default-marquee selection, fixture
callback identity, face-file completion, source-thread policy and assertions. It
now delegates input/Actor/animation/graph startup to production, then retains the
same loader/settings/global animation/faces/map/graph owners across its physical
construction and repeated ticks. No corpus checks are invoked by production.

Focused failure coverage checks missing mounted input, retained selected settings,
absence of later Actor work and rejection of a second whole-construction attempt.
Root owns Cargo and original-data validation; this packet makes no passing-data
claim. Physical pair construction and selected ticking are subsequent extraction
packets, not implemented here.
