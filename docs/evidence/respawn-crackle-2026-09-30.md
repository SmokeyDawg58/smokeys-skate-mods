## Marker trigger, queue and timing

`UpdateSessionMarker` runs in `PlayerUI::Update` when simulation is allowed,
the session marker exists and PlayerUI has focus. Input52/53 still comes from
the existing original `input.cfg` map and existing SIM input owner.

At 828af8e0..f930, after the established distance and permission checks, the
message amount is held time / required hold time, clamped to [0,1]. This is
sent even while `IsSafeToUseSessionMarker` refuses the actual teleport. The
original hold-time function and strict hold-time comparison remain unchanged.

Raw 828af8f4 is `bge` after an unordered compare: NaN takes the zero branch.
The implementation preserves this rather than using a Rust clamp that would
preserve NaN. It also preserves -0.0. Message kind is **0xa5be2e3b**, payload
size20, float at +0x10. The folded send function happens to carry the symbol
`SendMsg<cMsgSetSessionMarker>`; its concrete constructed kind identifies this
as `cMsgOutOfBoundaryAmount`.

When the teleport request is accepted, the existing snow counter becomes3.
At 828af97c..f9dc, a second message with amount1 overrides the earlier ramp,
then decrements the counter. The accepting update and the next two updates
therefore publish1. Releasing the input clears the latch/hold timer but does
not cancel these extra snow frames. Ordinary refusal, no input and an already
used marker after the extra frames send nothing.

`VDWriter` uses last-message-wins assignment, not maximum or addition. On each
native frame write, pending >=0 becomes `mNonPBDataLocation[1]`, then the writer
resets the pending field to -1 at 827fff9c. `VDReader` at 827fde60..e88 publishes
`bOutOfBounds` at output+436 from record presence and copies the amount to+440.
There is no easing or time decay. An absent frame record disables the effect;
a present record of0 still selects the noise variant and advances its clocks.

Host publication drains the marker producer once per completed simulation tick
and retains the resulting `Option<f32>` in the visual snapshot for all renders
of that tick. Source GameUI messages precede the eEQGameSim flush that tick.
This is the existing whole-tick presentation cadence, not a new fractional
DataSystem interpolation implementation.

## Original texture generation and constants

Texture setup at82831810..1840: 64x64, A8R8G8B8, one mip. Every pixel consumes
four RW random words in order R,G,B,A. For each word, extract bits8..15 and
write255 only when the byte is strictly greater than128; otherwise write0.
The native ARGB packed word is converted to the host's RGBA byte layout.

Important raw correction: the decompiler renders the last extraction as
`BYTE2(v14)`. Raw82831910 is `extrwi r11,r3,8,16`, exactly the same extraction
as the first three channels. Using the high-middle byte for alpha is wrong.

Noise sampler at828319bc..1a20: wrap on all axes, linear min/mag, no mip
filtering, sRGB enabled. Since stored channel values are binary, sRGB decoding
leaves each texel value unchanged before filtering. This is not a newly
generated independent noise texture every frame.

Phase globals83057094 (`noisedot1`) and83057090 (`noisedot2`) are both0 in the
original image. Each active final-noise draw adds0.045000002 and0.059999999 in
single precision; if phase>=4, subtract4 once. Each phase crossfades cyclically
between R->G->B->A->R using two nonzero adjacent weights. These phases advance
per active rendered frame, independent of sim delta or render delta, and stay
unchanged while the normal final shader is selected.

Four more RW random words supply unsigned low16 * 2^-16 UV offsets, stored in
reverse draw order in `g_NoiseScroll`: fourth, third, second, first. Existing
RW RNG seeding uses a host clock surrogate for native hardware timebase; full
original pre-game RNG consumption and exact grain pixels across runs are not
claimed identical.

`SetNoiseParameters` reads VD boundary amount, then clears its contribution if
`PauseMan::mMask & mFlags & 1`. Authored white noise remains. The final amount
is `fsel(whiteNoise+boundary-1, 1, whiteNoise+boundary)`, with no lower clamp.
Raw82828df4 writes amount to fade.y;82828e04..08 writes1-amount to fade.x.

## Final embedded shader

Extracted read-only to `%TEMP%/skate2-basictex-fisheye-noise.fpo`, disassembled
with the existing `tools/xenos_disasm.py`; no original bytes copied into code.
The shader itself contains reflection names and literal constants:

* tf0 BaseTexture, tf1 NoiseTexture, tf2 Vignette_texture.
* c0 g_Fisheye_Warp, c1 g_NoiseScroll, c2 g_NoiseFade,
  c3 g_NoiseDotP1, c4 g_NoiseDotP2, c5 g_VignetteUVOffset.
* First noise UV: uv*(10,5.625)+scroll.xy.
* Second noise UV: uv*(11,6.625)+scroll.zw.
* First/second samples are dotted with the respective channel weights.
* Noise signal in ALU source order is
  `saturate((((second+first)-2)+second)+first)`.
* Final RGBA: warpedScene*fade.x*saturate(vignette+c5.w)+noise*fade.y.

The shader uses the same fisheye scene sample/vignette evaluation as the
normal final program. The combined GPU pass owner is the fisheye workstream;
the root integrates shared renderer files. Applying an independent overlay
after the HUD would violate original ordering.

## OOB source audit and remaining boundary

Searching all `.text` words for the message-kind low halfword2e3b identifies
only the known receiver/binding functions and these native producers:

* PlayerUI marker update and dismissal callback828af178.
* `ChallengeCASManager::Update`825b8f58 (Create-A-Spot custom boundary).
* `InvisibleBoundaryManager::Update`82da72f0 (loaded challenge/online polygons).
* `cChallengeEffectsManager::Update`82daa1a0 (an active scripted OOB effect).
* Lua `cMsgOutOfBoundaryAmount_PostMessage_LuaBinding`828c6a98.

There is no direct snow producer in ordinary actor/physics teleport. Therefore
snow must not be attached indiscriminately to every respawn or inferred from
position jumps.

InvisibleBoundaryLoader82da6f48 reads a `challenges` Vault attribute, builds
`data/boundary/<name>.xml`, and loads the original polygon. The original
miscload.big contains many challenge/online district boundaries including
freeskate_waterfront.xml. GameLoad8273be50 loads such boundaries for party and
challenge paths; normal location-start free roam does not choose a district
polygon. Installing that waterfront polygon as a world edge would incorrectly
prevent travel to neighboring districts.

`InvisibleBoundaryManager::Update` measures distance to loaded polygon edges,
uses live boundary-warning cvars and emits the shared message near the edge.
`IsPositionOk`82da4d30 is reached by
`Simulation::TestForNetworkGameCollisionConstraints`8289e510. This is not proof
of an offline city-edge detector.

`cChallengeEffectsManager::Update` sends `(total-current)/total` for effect0
after decrementing current by dt; when current<0.001 it resets that effect.
Starting that effect is driven through the original Lua Effects binding.
Original ChallengeCore.bin contains compiled Lua chunks with StartEffect,
OOBTimerID and OutOfBoundsTimerID; the repository currently has no challenge
activity, trigger-volume message-group or Lua runtime for those producers.
Only its challenge message queue envelope exists. Those missing producers
cannot be replaced by a guessed height cutoff, rendered mesh bounds, or
forcing every teleport to show static.
