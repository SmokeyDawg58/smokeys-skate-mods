## Native selection and missing-manager semantics

`BreadCrumbManager::Implementation::GetSuggestedBreadCrumb` `0x82ce3060` uses an active override, otherwise `PopSuggestedRespawnPosition` `0x82ce2ef8`. The latter tries `GetWipeoutSpotBreadCrumb` `0x82ce1cb8`, then `PopBreadCrumb` `0x82ce2d80` (newest valid ring entry), then `GetLastResortBreadCrumb` `0x82ce2598`. The last resort uses the original spawn matrix at implementation `+0x10`, a fresh `Actor::GetFootForwardWithFakie`, and off-board false when the ring is empty (`0x82ce25b8..2608`); with a nonempty ring it copies the newest ring entry (`0x82ce2610..2678`). The constructor already drops the original spawn as an initial ring breadcrumb.

`TestForLWRespawnContraints` `0x82ce1320..14c8` first asks `INetworkGameQuery::IsNetworkGame`; true accepts without LivingWorld tests (`0x82ce1350..5c`). The selected local offline route is false and directly dereferences its `LWMan` argument to call virtual `DoesAnyVehicleIntersectSphere` (`+0x40`, `0x82ce139c`), `DoesAnyPedestrianIntersectSphere` (`+0x44`, `0x82ce13d8`), and `DoesAnyDynamicObjectIntersectCapsule` (`+0x48`, `0x82ce149c`), rejecting on the first hit. A null/unpublished LivingWorld manager has **no native empty result** on this route; an actually constructed empty manager can return three false answers.

The concrete `LivingWorld::Manager` vehicle query `0x82710760` obtains `LW::Man::GetVehicleMan`, requests vehicles in range, and returns false when the result count is zero (`0x8271081c`). The pedestrian query `0x82703600` obtains `LW::Man::GetPedestrianMan`, requests nearby pedestrians, and returns false when its count is zero (`0x82703698..a4`; disassembly, as Hex-Rays only shows the early part of this function). Dynamic-object capsule query `0x82703930` acquires a PhysicsWorld line batch with `BF_Dmo`, begins it, adds a capsule test, ends/syncs it, gets result zero, releases, and returns whether that result is nonzero (`0x827039b8..3a40`). Thus an empty DMO collision collection can provide a source-backed miss after this actual batch is mounted; an omitted query cannot.

## Wipeout candidate gates and existing Rust owners

`GetWipeoutSpotBreadCrumb` checks `kEnableWipeoutSpotBreadCrumb` (`0x82ce1cd8`), builds a candidate from last-known orientation/position, then requires `_TestForCollisionConstraints` (`0x82ce1d58`), `_TestForNavMeshConstraints` (`0x82ce1d70`), and the LivingWorld gate (`0x82ce1dc0`), in that order. `_TestForCollisionConstraints` `0x82ce19b0..1cb4` needs a downward `PhysicsUtility::LineWorldCollisionTest` hit (`0x82ce1a70`), tests its normal, distance and surface, then requires no obstruction from `IPhysicalWorldServices::LineCollisionTest` for the configured capsule (`0x82ce1c30`). In offline play it returns success after these tests (`0x82ce1c54`); network collision checks are another branch. `_TestForNavMeshConstraints` `0x82ce14d0..159c` accepts when its cvar is off, the game is networked, or `MeshStore::GetMeshCell` is invalid (`0x82ce14fc`, `0x82ce1518`, `0x82ce1550`); a valid cell requires `GetCellScore(cell, 0) < MaxNavMeshScoreForBreadCrumb` (`0x82ce1560..80`). An empty **constructed** MeshStore therefore passes this native navmesh gate.

Rust already has `ActorBreadCrumbManager` and `BreadCrumbSelectionSource` in `actor_breadcrumb_manager.rs`, the one retained `LivingWorldGrindServices` in `living_world_grind_services.rs`, initialized empty `EntityMan<24>/<40>` owners in `living_world_grind_entities.rs`, the empty-map `MeshStore::try_get_cell` in `living_world_mesh_store.rs`, and resident collision `CollisionScene::thin_segment_hits` in `world.rs`. The pedestrian range method exists; the vehicle range callback, respawn-oriented three-query LivingWorld bridge, `BF_Dmo` capsule batch, and exact breadcrumb collision/physics-island query are not yet connected. The generic static segment method alone does not establish the full native collision gate. The Actor breadcrumb manager is also not yet mounted by the selected session.

The original spawn breadcrumb is a valid *candidate*, but its selection is conditional: the wipeout candidate must fail and the ring entry must pass the live LivingWorld gates. Selecting the seed immediately from the spawn matrix would skip native tests. Minimum callable path: mount the Actor breadcrumb owner at its constructor point; retain/publish the same LivingWorld child managers and MeshStore; execute the wipeout collision, navmesh and LivingWorld gates; if rejected, scan the ring using the vehicle/pedestrian/DMO gates; then publish the chosen matrix through the already implemented `Actor::Teleport` writer. Constructor-empty results are valid only while the corresponding actual collections remain empty.
