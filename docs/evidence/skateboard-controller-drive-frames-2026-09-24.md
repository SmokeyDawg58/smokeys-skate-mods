# SkateboardController hand-drive frame update

`Sk8::Physics::SkateboardController::UpdateDriveFrames` is `0x82dcc408..0x82dcc618` in the Skate 2 debug build. It is called at `0x82dcc71c` by `EnableHandDrive` after its dynamics writes. Its own first read is the live `kSKC_UseHandDrives` target; false returns without inspecting the selected hand, animation, or frames. True asserts if `mHandHoldingSkateboard == eNumHandDrives` (2) at `0x82dcc440..458`. Hand 0 selects `PART_LEFTHAND` (3); otherwise it selects `PART_RIGHTHAND` (7). The PDB `PartIndex` and existing `ragdoll::SkeletonPartIndex` corroborate root 0, left 3, right 7.

The method calls `Skeleton::GetAnimPartTransform` (`0x82b3b928`) for `PART_SKATEBOARD_ROOT` (0) at `0x82dcc47c`, then the selected hand at `0x82dcc48c`. That getter copies four complete 16-byte animation-volume columns. The arithmetic in `UpdateDriveFrames` makes an identity child matrix and a hand matrix relative to the animated skateboard root: transpose the root's rotation, subtract its translation, then compose with the hand transform. It calls `rw::physics::DriveFrames::SetChildFrame` at `0x82dcc5e4`, then `SetParentFrame` at `0x82dcc5fc`, both on `mDriveFrames[mHandHoldingSkateboard]`. The setters (`0x82b25248`, `0x82b23470`) share the existing `world::try_simulation_quaternion_candidate` matrix conversion graph; each then copies all four translation lanes to its own frame half. No final rigid-body quaternion normalization belongs to these frame setters.

`skateboard_controller_drive_frames.rs` uses the controller's actual retained `Arc<RwLock<SimulationDriveFrames>>` slot, existing rigid inverse/composition helpers, and the shared quaternion candidate. The isolated method takes a live cvar read, two animated-part reads, and the reciprocal-square-root estimate service as callbacks, preserving source read order and the child write if the later parent conversion fails. Focused tests check the gated return, selected right-hand Part order and same-slot write, and a late parent failure. An additional geometric discriminator gives root a +90-degree Z rotation and places a world-aligned hand two world-Y units from it. The expected child frame remains identity; the parent frame is at local +X with a -90-degree Z rotation. This checks the source root-relative orientation without using the implementation's matrix composition as the expected value. This method is not yet connected to the live Hold caller; the containing physical transition remains at its explicit StartController boundary until all board animation and hand-drive collaborators are wired. Host matrix arithmetic and reciprocal-square-root estimates have not been shown bit-identical to Xenon for exceptional or nonorthogonal animation matrices. No Cargo build was run in this delegated task.
