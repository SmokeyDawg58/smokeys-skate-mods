# Gameplay messages to the retained Actor listener

2026-09-08, read-only original PDB/IDA and repository audit. No Rust edits or Cargo. Raw-confirmed ordering is distinguished below from remaining generated-controller work. This follows the now implemented command-owned gameplay pad, recognizer histories/matchers, and retained typed message producer; the older input-actor-next-closure packet predates those implementations.

## Concrete next closure and its endpoint

The next useful consumer is the SAME Actor's retained ActionGraphInputListener, subscribed to the SAME workspace gameplay broadcaster, receiving ordered match/held messages and retaining native action events. Original Ollie produces an InputPattern event carrying its original name and normalized speed. The source event-to-intent suffix inserts Trick=1, Ollie=1, GestureSpeed=matched speed. It does not set RawPhysIn.startJump directly.

Only Kickflip, Heelflip, N_Kickflip, and N_Heelflip become holding candidates. An Ollie held message alone does NOT create HoldPattern. No release message exists: a matching flip's held message sets a latch; Fill consumes and clears that latch, and a later frame without another held message produces no HoldPattern. Candidate name itself is not cleared by this absence. A corpus that expects Ollie held messages to drive HoldPattern would invent behavior.
