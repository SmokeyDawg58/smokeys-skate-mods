Integration result: the corrected patch was independently IDA-reviewed and
registered as `camera_producer_projection.rs`, using the existing camera
observer and retained producer. The original mounted baseline passed 23/23 in
`artifacts/original-baseline-camera-producer-typed-2026-09-23.log`, the workspace

## What it provides

The draft adds an immutable query on the **existing** `SkaterObserverState::Camera` → `CameraStartupFields` → retained `CameraMan` chain. A host-only producer_snapshot_ready capability starts false, is cleared at selected local-change and at the entry of every selected camera update, and becomes true only after CameraMan::try_update_prefix returns Ok. The query returns NoCompletedSelectedUpdate until then. This avoids using CameraMan.update_counter as a success stamp: native-order counter publication precedes later failure points. It copies ordinary `CameraMan.frame.matrix`, `previous_matrix`, frame FOV, hard cut, index override and update counter under the same owner lock; current and previous matrices remain `SkeletonRootMatrix` values with their exact `Option<f32>` W lanes. No source W is fabricated. It reads retained `CameraAttributes.bindings[18]` far `+0x64` first, then live near cvar through `InputCvarReferences::try_camera_near_clip_distance()` (index 330), then rendering override flag `+0x5a`. The rendering override FOV `+0x60` is read only when the flag is enabled; otherwise the captured frame FOV is selected. Each layout access remains checked and typed. The output carries typed source and previous matrices, chosen FOV/near/far, a numeric view whose W is established by the renderer, projection and clip-from-world. The type name is `CameraProducerProjection` so it cannot be mistaken for a presentation restore result.

`CameraAttributes.bindings[18]` is a **provisional shared-Vault proxy**. Native `CameraPresentation` constructs a separate `Attrib::Gen::rendering` instance at `827f2190..94`, while `CameraAttribManager` owns the camera-attribute instance. Both initially bind mounted class `1FFDC8E3ACA07C1F`, default collection `D7EDBD362D7D2152`; their future mutation equivalence is not proven. The draft deliberately does not add a second host camera, attribute loader or cvar store. A parity presentation implementation must replace this proxy with its own retained instance.

For the interim static-map view, the draft reuses `world::inverse_collision_affine_reset` to compute the full 3×3 cofactor inverse and translated origin. It replaces only the output homogeneous W lanes with `RenderMan::UpdateCamera82848978`'s canonical view W stores. This is a **host numeric approximation** to the renderer's VMX graph, not a claim of exact Xenon reciprocal-estimate rounding. The projection follows `ViewCamera::SetPerspectiveMatrixRadians82840770`'s ordinary finite zero-jitter scalar path: FOV degrees × `0x3c8efa35`, normalized angle × `0x3f22f983`, hard-coded double 16/9, negative clip-X scale, positive Y, positive camera-Z forward, and D3D 0..1 depth terms `far/(far-near)` and `far*near/(near-far)`. The patch supplies a column-major clip-from-world product for the app's existing GPU matrix contract. Stereoscopy, jitter, manual/ICE/NIS/static/ghost camera selection and native presentation interpolation are outside this provisional output.

Three pure module tests are included for root validation: a nonorthogonal 2× camera scale plus translation verifies that view construction uses the full inverse instead of a transpose; another varies the chosen FOV to verify projection math. The third sets every source W to unknown and checks that typed source W remains unknown while view and clip XYZ remain identical. These pure tests do not exercise retained binding or cvar lookup. The mounted parser probe separately proves default override-off, 60-degree override value, 7700-m far plane, and the existing cvar owner provides initial near 0.1 m. Those numbers are read from retained runtime owners by the draft, never embedded as runtime tuning.

Independent review corrected the scalar access order: the earlier aggregate helper read override flag, override FOV and far before the near cvar. The revised accessor performs separate far, near and FOV reads in native `RenderMan::UpdateCamera82848978` getter order. `CameraPresentation::GetFOVY827f64b0` only loads rendering layout `+0x60` after a nonzero `+0x5a` flag on the normal branch; the host proxy now does the same. If near fails, no FOV layout read occurs; if far fails, neither near nor FOV is sampled. The frame FOV itself is captured under the CameraMan owner lock with the matrix to keep a coherent producer snapshot; only its selection into the renderer scalar occurs after far and near. The native presentation frame remains a distinct owner.

The patch extends the existing mounted three-frame corpus only when its selected camera subsequence is enabled. After each completed tick, it invokes the same retained local manager's observer accessor, records current and previous optional W bits by column, compares the near value to live cvar330, checks mounted default rendering far=7700 and override-off, and prints the two optional W quartets by frame. The first all-f32 draft failed the mounted frame-0 test with `CameraProjection(UnknownMatrixW)` (`artifacts/original-camera-producer-w-probe-2026-09-23.log`). The typed revision passed the mounted selected three-frame probe, 1/1, in `artifacts/original-camera-producer-typed-w-probe-2026-09-23.log`. Its far=7700, override-off, live near-cvar and per-frame update-counter assertions passed. It preserves unknown W rather than synthesizing an affine lane.

## Exact limitations and integration boundary

The draft selects the ordinary `CameraMan.frame`, consistent with default `kbUsePhysOutCamera=false` at initializer `82fa22f8`; this debug cvar is not in retained `InputCvarReferences`, so the output must remain named provisional for sessions that change it. The first all-f32 draft required full known W and failed at mounted frame 0. The revised output keeps each source matrix typed, calls the existing inverse helper using only its XYZ-consuming scratch, and replaces the helper output W with the source-established canonical renderer W. The temporary scratch W does not escape. This produces a numeric view without making the native source CameraFrame fully known. The success precondition is enforced in the retained owner. The mounted probe shows that the first three current basis W lanes are known but are not canonical affine 0 values; the fourth, translation W remains unknown on frames 0, 1 and 2. The previous matrix has the same observed W quartet on each corresponding frame, without proving that the full matrices are equal or why the previous selector chose those lanes. This matches the source: framing writes known basis W, while calculate_position_with_shake preserves anchor/shake W into positioner position, which becomes the fourth CameraFrame column before Shake Apply.

The mounted W observations (column order 0, 1, 2, 3; current and previous agree within each frame) are:

| Frame | Basis W raw bits | Translation W |
|---|---|---|
| 0 | `bf7fffd0 ba5f39c5 3b0d6427` | `None` |
| 1 | `bf7fff04 bb0cea81 bba343c5` | `None` |
| 2 | `bf7fffb3 badbc655 bb24025c` | `None` |

These are retained **producer** observations after successful selected ticks, not restored presentation or drawn-frame matrices. In particular, filling column-3 W with 1 or basis W with 0 would contradict the retained values and is unnecessary for the bounded renderer view calculation.

## Native W-lane dependency proof for the typed revision

Read-only IDA at `RenderMan::UpdateCamera82848978`: `GetMatrix` returns the full source matrix at `828489c0`; vectors 0/1/2 and translation load at `828489cc..48a24`. `vpermwi 0x63` at `828489d8/f0/f8` cycles XYZ and leaves W in lane 3. The cofactor multiply/`vnmsubfp` sequence `82848a08..48a64` is lane-wise, so source W remains in W and cannot enter cofactor XYZ. `vmsum3fp` at `82848a6c` reduces only the three XYZ determinant lanes. After `vrefp` and two refinements, the inverse basis is transposed/scaled; `stfs` at `82848ac0/c4/dc` establishes basis W as zero. Translation is splatted only from the sign-flipped source translation lanes 0, 1, 2 at `82848a44/4c/54`, combined at `82848ac8/cc`, then its W is established as one at `82848b04` before `SetViewMatrix82848b28`. Therefore no unknown source W reaches numeric view XYZ or published view W on the ordinary path. The current `world::inverse_collision_affine_reset` likewise computes cofactor/determinant/translation XYZ only from matrix XYZ and the bridge resets its W before publication. This is a host numeric approximation, with Xenon reciprocal estimate/rounding still unresolved.

The source of the unknown remains typed upstream: `CameraMan::try_update_rig_subject_matrix` copies the selected `Subject.anchor_position` into `Rig.anchor_matrix` column 3; the positioner receives the anchor tracker vector and `calculate_position_with_shake` combines it lane-wise with local offset/shake, retaining unknown W. `CameraFrame::try_publish_frame` passes that full position vector as input column 3 to `ShakeEffect::Apply`; its returned W depends on input W, never on the discarded keyframe W. The normal frame copy therefore cannot claim a fully known affine matrix. The per-column mounted probe resolved the original failure to translation column W: basis columns 0/1/2 are Some and column 3 is None in all three current and previous samples.

No `CameraManager::UpdateChannels`, `CameraPresentation::DoSimSubmit/DoSimRestore`, `RealTimeController` frame selection, hard-cut endpoint choice or interpolation percent is implemented by this draft. The native render schedule and mounted values are proved in `live-camera-renderer-view-projection-2026-09-23.md` and `mounted-camera-render-presentation-schedule-2026-09-23.md`. The draft has an internal core observer query but no public playable app session invokes it yet; root must connect that existing session to the interim static-map renderer before any visual claim. A screenshot produced from this projection would show the camera producer after a tick, **not** the exact native first drawn frame.
