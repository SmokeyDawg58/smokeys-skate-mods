# Local bail respawn: LivingWorld query bridge boundary

This audits the three offline `LWMan` callbacks reached by `BreadCrumbManager::Implementation::TestForLWRespawnContraints` `0x82ce1320`. A deliberately limited first-test host adapter now queries the retained constructed-empty child stores and the reviewed DMO capsule batch in native order. The complete `LivingWorld::Manager` and its child query globals have not been published by selected host initialization, so this adapter is not a native Manager initialization claim.

## Native order and actual empty paths

`TestForLWRespawnContraints` first returns true for a network game at `0x82ce1350..1354`. Offline it reads the candidate matrix translation and calls vehicle sphere at `0x82ce139c`, pedestrian sphere at `0x82ce13d8`, and DMO capsule at `0x82ce14bc`, stopping on the first hit. It directly dereferences `LWMan`; a null or unpublished Manager cannot be interpreted as three misses. It gets the DMO capsule height and radius from `skater_breadcrumbs` attributes at `0x82ce13fc..1418` before building the endpoints at `0x82ce1454..14b8`.

`LivingWorld::Manager::DoesAnyVehicleIntersectSphere` `0x82710760` calls `LW::Man::GetVehicleMan` at `0x827107e4`, then virtual `GetVehiclesWithinRange` at `0x8271080c`; zero count returns false at `0x8271081c`. The concrete `LWVehicleMan::GetVehiclesWithinRange` `0x82d29030..44` clamps requested items to 24 and passes its `EntityMan` KD tree to `FindNear` `0x82d28c00`. That KD tree writes the result count to zero at `0x82d28c34` and exits without walking when root `+0x1c` is null at `0x82d28c5c..64`.

`LivingWorld::Manager::DoesAnyPedestrianIntersectSphere` `0x82703600` calls `GetPedestrianMan` at `0x8270366c`, then virtual `GetPedestriansWithinRange` at `0x82703694`; the returned zero count branches to false at `0x82703698..a4` (the full disassembly is required here because decompilation truncates the populated branch). `LWPedestrianMan::GetPedestriansWithinRange` `0x82e9ab88..9c` clamps to 40 and reaches the same KD `FindNear`. The existing `LivingWorldGrindServices::try_get_pedestrians_within_range` uses the retained published pedestrian manager and the exact null-root method, rejecting missing construction or a populated roster/tree.

`LivingWorld::Manager::DoesAnyDynamicObjectIntersectCapsule` `0x82703930` checks the Simulation singleton and `mWorkspace.mPhysicsWorld` at `0x8270394c..98`; it acquires `"LWMan::DynamicObjectTest"`, flag `BF_Dmo` = 2 at `0x82703998..b8`, then Begin `0x827039c8`, capsule AddTest with both endpoints and radius `0x827039e8`, End `0x827039fc`, Sync `0x82703a10`, GetResult(0) `0x82703a30`, and Release `0x82703a40`. It returns whether the result pointer was nonzero at `0x82703a44..4c`. A constructed empty DMO collision pool can give a native miss after this complete sequence; checking the separate LivingWorld DMO `EntityMan` map would query the wrong owner.

## Retained host owners and missing link

`PhysicalGrindServices::new` retains one `Arc<Mutex<LivingWorldGrindServices>>`. Its selected entity initialization allocates and initializes separate pedestrian (40), vehicle (24), and DMO (50) `EntityMan` stores. `EntityMan::try_find_near_constructor_empty` proves a zero count only after initialization and only for a null KD root with an empty roster. The new vehicle wrapper uses this method with the native 24-item clamp and an explicit missing-manager error. The current service does **not** publish a complete `LivingWorld::Manager` or the global `LWMan` query token; `pedestrian_man_published` is a selected submanager token only.

IDA makes the publication dependency concrete. `LivingWorld::Manager::Init` `0x8271f6f0` calls `InitLWMan` at `0x8271f700` before later child initialization. The `InitLWMan` body `0x82702da8..0x82703148` first binds debug overlay, asset/character managers, state cache, broadcasters, inventory, PhysicsWorld, SkaterMan, playback, painter, spatial manager and random; it then calls `LW::Init::InitLWManager(this)` at `0x827030b0`, `InitPedestrianMan(&this->mPedestrianMan)` at `0x827030c4`, `InitVehicleMan(&this->mVehicleMan)` at `0x827030cc`, and `InitDynamicObjectMan(&this->mDynamicObjectMan)` at `0x827030dc`. The four small publishers write separate global pointers: `gpLWManager` at `0x82e4f28c`, `gpPedestrianMan` at `0x82e4f37c`, `gpVehicleMan` at `0x82e4f38c`, and `gpDynamicObjectMan` at `0x82e4f3ac`. `LW::Man::GetVehicleMan` `0x82e4f0c8` asserts if `gpVehicleMan` is null; the pedestrian getter `0x82e4f078` has the same null check. The retained Rust selected initialization does not execute the preceding required service bindings or full manager construction, so treating its selected child initialization as all four global publications would invent a Manager state.

`SimulationWorldLineQueries` now implements `try_dmo_capsule_test` on the same retained World/Island line batch: the native capsule call is the existing line `AddTest` with start, end and fatness, flag 2, followed by End/Sync/GetResult/Release. The scoped `physical_player_living_world_respawn.rs` host adapter requires the Actor-supplied LivingWorld Arc to be the exact Arc retained by `PhysicalGrindServices`, and checks initialized pedestrian/vehicle/DMO EntityMan stores before querying.
