## Concrete call chain

The renderer patch stores the actual `wgpu::Device` and `wgpu::Queue` in `Arc`s and exposes a cloneable `GpuTextureUploader` from `GpuRenderer::texture_uploader`. `GpuRenderer::upload_native_texture` delegates to that same uploader method, so the resident path and existing diagnostic path use one upload implementation and the same actual device/queue. No second GPU device, texture parser, or texture inventory is created. A renderer-bearing client can get the owned uploader during `initialize`, supply it with the accepted PROXY catalog and selected parent ID to `Kind0ResidentBuilderSessions`, then pass that session factory into the existing `CatalogResidentCollectionLoadFactory` and retained `CollectionResidentStreamer` with `OwnedResidentCollectionStorage<Kind0ResidentArenaAsset, ..>`.

The new session factory verifies the exact selected collection snapshot against the existing catalog, requires Presentation kind, and rejects a zero-asset parent. Each `CollectionAssetBuilder::build` first calls `DecodedArenaAssetBuilder`, verifies the one-row Texture TOC branch and same-arena Texture/GPU-buffer locators with existing parsers, calls `own_texture_arena` on that **same decoded asset**, and uses the owned uploader before returning the resident value. That value retains the decoded arena and a distinct boxed kind-0 product containing full outer/TOC IDs, both checked dictionary indexes **and resource ranges**, the parsed source `Texture` including serialized fetch words, same-format alias dimensions/format with separate alias bit, and the owned `GpuTexture`. The Box address is stable while its resident asset remains alive; `alias_identity()` offers a pointer identity for the already reviewed shader table. This is a portable host identity, not the native Xbox `Texture*` or a copied serialized fetch address. The resident declares `alias` before `decoded`, so Rust drops the alias/GPU allocation before its decoded source.

Native `ProcessArena` selects the first **exported** TOC object. The current parsed `Arena` exposes dictionary entries, not an exported-object iterator. The draft requires exactly one dictionary TOC and rejects any second TOC. This is a deliberately narrower admission for the observed single-TOC parent arenas, not a claim that dictionary-wide scanning reproduces the native first-exported selection for arbitrary arenas.

Because the existing resident load driver invokes the builder before completing the physical request, a decode, locator, or GPU upload error stops that request before its parent/spatial load callback. The draft does **not** send or acknowledge a callback. The session factory accepts only the supplied parent ID, so it cannot silently process arbitrary spatial kind-2/10 arenas as kind-0. Parent first-use Presentation registration, shader-table insertion/removal, external resident holds, and PROXY load/activation counters still require the retained Presentation registry and boot owner identified in the prior evidence. The draft must not be presented as completed kind-0 registration or enabled PROXY boot.

## Native anchors and host boundary

`ProcessArena82d60058..82d601cc` selects one Texture TOC row, builds a distinct 0x34 alias header, and registers kind 0 before the resident callback; `RegisterTexture82d5ea00` passes its distinct pointer and full TOC ID into the processed asset list. `Presentation::RegArena827f156c` and `DRegArena827f17bc` use that same pointer and ID for shader insertion/removal. The draft's Box and owned GPU upload provide the corresponding stable host allocation and render resource, but do not reproduce the Xbox header words. Native `GetAliasedParameters82bca7a4` reads the post-fixup fetch address from `Format.dword[1]`; `Texture::parse` exposes serialized fetch words/ObjectId. A future processed registry must bind the checked locator to the same product, preserve first/last-use ordering, and release the resident only after removal. It must not fabricate the fixed-up address.

## Review and validation limits

The patch is intentionally separate from the registered renderer; root can inspect and apply it as one bounded change. The draft has not been compiled because delegated work was prohibited from Cargo. A retained-streamer caller would need an accepted PROXY catalog/parent ID and a concrete `CollectionParentEffects` Presentation receiver that resolves the **same** resident collection into processed kind-0 entries, uses the existing shader table for first/last-use identity, and delivers the separate callback/hold releases. No such receiver is registered yet, so adding a caller that returns successful parent effects would lie about native completion. The table remains unregistered and crate-private; this packet does not add a duplicate table. A focused mounted follow-up should verify all 93 observed parent products and TOC IDs, exact locators/ranges, GPU upload success, before-callback construction, and failure prefix. It then needs the real parent Presentation registration effect and same-identity removal before any load/activation completion claim.
