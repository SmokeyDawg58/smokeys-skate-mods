# PROXY Presentation kind 0 and kind 2 production audit

Read-only source/plumbing audit for the first rendered proxy test. The exact new-file path was checked with `Test-Path` and absent before writing. No registered Rust source or Cargo command was changed. Evidence is the PROXY parent census, `proxy-parent-asset-producer-audit-2026-09-23.md`, current Rust callers, and live IDA disassembly/decompilation. Confidence is high for the call graph and exact for cited PPC branches; Rust manager execution is absent.

## Reference effects, in actual order

`cProcessArenaAsset::ProcessArena` (`0x82d5fee0`, special test `0x82d60058`) takes the single-row Texture TOC branch for **all 180 observed PROXY texture arena occurrences** (93 parent, 87 spatial). That branch gets texture parameters (`0x82d600f8`), aliased parameters (`0x82d60108`), the resource descriptor (`0x82d60114`), allocates a new resource (`0x82d60168`), initializes `renderengine::Texture` (`0x82d60180`), then calls `RegisterTexture` (`0x82d601cc`). It does not use ordinary `ProcessTexture`, whose resource descriptor is zeroed. `RegisterTexture` (`0x82d5ea00`) stores the Texture pointer plus five resource bases in its wrapper, calls `AddPresRegistryAsset` (`0x82d5eabc`) for kind 0, then appends the processed product (`0x82d5eac8`). Alias parameters, allocation, source-resource lifetime, and the wrapper therefore belong to the required producer effect; linear pixel decode alone cannot replace them.

`Presentation::RegArena` (`0x827f1430`) walks the processed list forward. Kind 0 (`0x827f155c–0x827f156c`) passes the wrapper's texture pointer and full 64-bit TOC asset ID to **`Sk8::ShaderSystem::gTexMan.AddTexture`** (`0x82e1b058`). Kind 2 (`0x827f1574–0x827f1580`) passes a whole mutable `tRMaterialData*` to **`Sk8::Render::GfxMan->TextureMan.AddMaterial`** (`0x8282c838`), not the material TOC GUID. These are separate managers. Parent-first collection registration matters because spatial kind-2 material channels can resolve parent texture products.

`AddTexture` first calls `FindTexture` (`0x82e1a090`), which keys its table by the full 64-bit asset ID with low bit cleared (`clrrdi r11,r4,1` at `0x82e1a0a0`). On a new key it takes a free slot, records the normalized ID, and sets active/high/low texture pointers to the new texture (`0x82e1b0bc–0x82e1b10c`). For an existing key, an odd ID replaces low resolution only (`0x82e1b118–0x82e1b140`); an even ID replaces high and active (`0x82e1b14c–0x82e1b168`). IDA pseudocode garbles the 64-bit key's high half; the PPC `clrrdi` and `std` are decisive. A plain GUID-to-texture map misses this high/low/active state.

`AddMaterial` (`0x8282c838`) walks materials forward and channels from index 2 (`0x8282c880–0x8282c9b4`). It skips flags bit 1 (`0x8282c8a4–0x8282c8b0`) and the **full 64-bit** invalid asset ID (`cmpld` at `0x8282c8b8`). For each remaining channel it queries the asset registry for `guid | 1` (`0x8282c8c8–0x8282c8d8`), then `guid & ~1` (`clrrdi` at `0x8282c8ec`, lookup at `0x8282c8f8`), then the configured `GfxMan->mMissingTextureAssetID` (`0x8282c908–0x8282c918`). A missing fallback asserts. It asserts that `m_pStream` is null (`0x8282c940`), calls shader `FindTexture` with the channel GUID (`0x8282c960–0x8282c968`), and writes either a special table-index form or the selected registry asset data's first stream word into that channel (`0x8282c96c–0x8282c98c`). Thus fallback lookup and actual mutable stream binding are required; resolved GUID counts do not constitute kind-2 activation.

## Existing Rust boundary and reusable parts

`DecodedArenaAssetBuilder` and `DecodedArenaAsset` (`decoded_arena_asset.rs`) already retain the generic XST format-2 decoded resources, RW4 arena, asset ID, and five XST resource descriptors. `OwnedResidentCollectionStorage<DecodedArenaAsset, ..>` / `OwnedResidentAssetsView` (`owned_resident_collection.rs`) retain collection membership and expose authored-order assets without inventing another loader. The existing catalog, `CollectionParentManager`, resident streamer, and mounted load driver provide the required closure, first-use callbacks, and resident lifetime. `ArenaRegistrationRefCounter` (`arena_registration_ref_counter.rs`) is directly reusable for Presentation arena first/last-use coalescing, distinct from collection loaded counts and the shader texture table.

`own_texture_arena` (`mounted_character_scene.rs:147`) parses TOC identity, Texture and GPU buffer objects and provides `NativeTexture` encoded/linear levels; `TextureScene` and `ResidentTextureHandle` (`texture.rs`) are useful host rendering inventory. They do **not** preserve the aliased resource construction as a registered manager product and are not `gTexMan`. `PresentationScene::bind_resident_textures` (`presentation.rs:260`) checks exact GUIDs in a scene index, skips channels by names, and stores optional host handles. It does not perform channel-index-2/flags/native asset lookup, fallback, or mutation of the original material stream field. It is not `TextureMan::AddMaterial`.

`PresentationDmoArenaDispatch::add_material` and `PresentationMaterialDataHandle` (`presentation_dmo_arena_adapter.rs:74,115`) record the correct whole-source/owner-identity idea, but the handle is tied to `Arc<SimulationStaticArenaPlan>` and the prepared adapter is main-DMO-bank scoped. Its dispatch implementations are test probes; no production `TextureMan` binding implementation was found. Reuse its locator/identity design, not its DMO authority or a copied `PresentationMaterial` value. The PROXY source should be owner-bound to its existing resident `DecodedArenaAsset`; mutable materialized channel state must stay associated with that backing object and be cleared on deregistration.

## Smallest coherent seam and scoped first packet

The implementation seam is the Presentation registration receiver over the **existing retained decoded resident asset owner**, after parent and child load callbacks and before proxy activation acknowledgement. Prepare an ordered processed-asset sequence from the first used TOC, with a distinct single-Texture alias path and ordinary material path. Keep full TOC IDs, arena ID, resource/object locator, and original owner for each product. Use `ArenaRegistrationRefCounter` so each arena's kind-0/kind-2 effects occur only on Presentation first use; send the separate activation completion only after those effects succeed. No new XSS parser or independent stream driver is needed.

A useful first isolated packet can implement and validate the **kind-0 producer plus shader texture table** for the 93 parent Texture arenas, including alias allocation/resource ownership, normalized 64-bit key, free slot and odd/even active/high/low transitions. It may report produced and registered kind-0 results, but cannot claim PROXY activation, since 147 spatial kind-2 material bindings and admitted kind-10 Environment effects remain. The following kind-2 packet must add an asset-registry view over the same retained processed products, a source-backed configured missing-texture asset, and mutable owner-bound channel stream binding with the exact lookup/failure order above. If the configured fallback is unavailable, fail the packet explicitly; do not substitute a zero/placeholder texture or treat scene-level GUID resolution as registration.
